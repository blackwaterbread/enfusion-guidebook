<Objectives>

- 반환 타입과 매개변수를 갖춘 함수와 메서드를 선언하고 호출할 수 있다.
- 기본값과 이름 있는 인수(named argument)로 호출을 간결하게 만들 수 있다.
- `out`, `inout`, `notnull`, `const` 매개변수 수식어의 뜻을 알고 상황에 맞게 쓸 수 있다.
- 오버로드와 재귀를 공식 코드의 관례에 맞게 쓸 수 있다.
- 메서드를 다른 함수에 넘기는 `func` 타입의 쓰임과, `thread` 키워드를 게임 코드에서 피하는 이유를 설명할 수 있다.

</Objectives>

지금까지의 예제는 이미 함수 안에 들어 있었습니다. 1장에서 본 것처럼 실행할 코드는 모두 함수 안에 있어야 하기 때문입니다. 이 장에서는 함수를 선언하는 규칙, 값을 주고받는 방법, 같은 이름의 함수를 여러 개 두는 오버로드, 그리고 함수를 값처럼 넘기는 방법을 다룹니다.

엔진 문서는 함수가 반환 타입, 이름, 매개변수 목록으로 이루어지며, 전역 스코프에도 클래스 안에도 선언할 수 있다고 설명합니다. 클래스 안에 선언한 함수를 **메서드**(method)라고 부릅니다. 이 장의 예제는 대부분 정적 메서드로 썼기 때문에, 객체를 만들지 않고 Remote Console에서 `클래스이름.메서드이름()`으로 바로 실행해 볼 수 있습니다. 클래스와 객체는 5장에서 본격적으로 다룹니다.

## 함수 선언과 반환값

### 선언 형태

함수는 `반환타입 이름(매개변수 목록)` 다음에 중괄호 블록을 둡니다. 매개변수마다 타입을 적고, 값을 돌려줄 때는 `return`을 씁니다. 공식 컨벤션에 따라 함수 이름은 PascalCase, 매개변수 이름은 camelCase로 씁니다.

```enforce title="Scripts/Game/TAG_MathUtils.c"
class TAG_MathUtils
{
	//------------------------------------------------------------------------------------------------
	//! 두 정수의 합을 돌려줍니다.
	static int Add(int a, int b)
	{
		return a + b;
	}

	//------------------------------------------------------------------------------------------------
	//! 두 정수의 평균을 실수로 돌려줍니다.
	static float Average(int a, int b)
	{
		return (a + b) / 2.0;
	}

	//------------------------------------------------------------------------------------------------
	//! 아무것도 돌려주지 않는 함수는 반환 타입이 void입니다.
	static void PrintSum(int a, int b)
	{
		PrintFormat("%1 + %2 = %3", a, b, Add(a, b));
	}
}
```

`TAG_MathUtils.PrintSum(2, 3);`을 실행하면 `2 + 3 = 5`가 출력됩니다. 같은 클래스의 정적 메서드끼리는 `Add(a, b)`처럼 클래스 이름 없이 부를 수 있습니다. `Average`에서 `2.0`으로 나눈 것은 실수 나눗셈임을 드러내기 위해서입니다. 1.8.0.13에서는 `float`를 돌려주는 `return`의 `(a + b) / 2`도 실수로 계산되지만, 같은 식을 `int` 변수에 담거나 `Print`에 넘기면 버려지므로(2장) 한쪽을 실수로 두는 편이 안전합니다.

<Compare title="두 수를 더하는 함수">

```python
def add(a, b):
    return a + b
```

```javascript
function add(a, b) {
  return a + b;
}
```

```csharp
static int Add(int a, int b)
{
    return a + b;
}
```

```enforce
static int Add(int a, int b)
{
	return a + b;
}
```

</Compare>

C#을 써 본 사람에게는 거의 같은 모양입니다. Python과 JavaScript에 익숙하다면, 매개변수와 반환값의 타입을 반드시 적어야 하고 그 타입이 컴파일할 때 검사된다는 점이 가장 큰 차이입니다.

### 모든 경로에서 값 돌려주기

반환 타입이 `void`가 아니면 어느 경로로 끝나든 값을 돌려줘야 합니다. `if`와 `else`의 양쪽에서 모두 `return`하는 것은 공식 코드에서도 흔한 형태입니다. 3장에서 본 것처럼 `switch`로 끝나는 경우에는, 모든 `case`가 `return`하더라도 공식 코드처럼 `switch` 뒤에 `return`을 하나 더 둡니다.

```enforce
static string DescribeHealth(int health)
{
	if (health > 0)
		return "alive";
	else
		return "dead";
}
```

`void` 함수에서는 값 없이 `return;`만 써서 함수를 일찍 끝낼 수 있습니다. 3장의 조기 `return` 관용구가 이것입니다.

## 매개변수

### 값으로 넘기기와 참조로 넘기기

인수를 넘기는 방식은 2장의 규칙을 그대로 따릅니다. `int`, `float`, `bool`, `string`, `vector` 같은 값 타입은 복사되어 넘어가므로, 엔진 문서의 설명대로 함수 안에서 매개변수를 바꿔도 호출한 쪽의 변수는 그대로입니다. 배열과 객체는 참조로 넘어가므로 함수 안에서 내용을 바꾸면 호출한 쪽에서도 보입니다.

```enforce
static void TryToChange(int number, array<int> numbers)
{
	number = 100;           // 복사본만 바뀜
	numbers.Insert(100);    // 호출한 쪽의 배열에 원소가 추가됨
}
```

```enforce
int value = 1;
array<int> list = { 1 };
TryToChange(value, list);
// value는 여전히 1, list는 { 1, 100 }
```

값을 돌려받으려면 반환값을 쓰거나 아래의 `out` 매개변수를 씁니다.

### 기본값

매개변수 뒤에 `= 값`을 붙이면 호출할 때 그 인수를 생략할 수 있습니다. 공식 스크립트에서도 기본값이 붙은 매개변수는 모두 목록의 뒤쪽에 있습니다. 기본값 없는 매개변수를 앞에, 기본값 있는 매개변수를 뒤에 둡니다.

```enforce title="Scripts/Game/TAG_HealthRules.c"
class TAG_HealthRules
{
	//------------------------------------------------------------------------------------------------
	//! health를 amount만큼 회복하되 maxHealth를 넘지 않게 합니다.
	static int Heal(int health, int amount = 25, int maxHealth = 100)
	{
		int result = health + amount;
		if (result > maxHealth)
			result = maxHealth;

		return result;
	}
}
```

| 호출 | 결과 | 설명 |
|---|---|---|
| `Heal(50)` | `75` | `amount`와 `maxHealth`에 기본값 사용 |
| `Heal(50, 60)` | `100` | `maxHealth`의 기본값 100에서 멈춤 |
| `Heal(50, maxHealth: 200)` | `75` | `amount`는 기본값, `maxHealth`만 지정 |
| `Heal(50, maxHealth: 200, amount: 80)` | `130` | 이름 있는 인수는 순서를 바꿔도 됨 |

### 이름 있는 인수

표의 마지막 두 줄처럼 `매개변수이름: 값` 형태로 인수를 넘길 수 있습니다. 엔진 문서에 따르면 이름 있는 인수는 순서대로 넘기는 인수 뒤에 두며, 그 안에서는 순서를 바꿔도 됩니다. 엔진 문서의 예인 `num.ToString(5, prefix: "#", hex: true)`는 `123`을 `"#0007B"`로 바꿉니다.

이름 있는 인수는 기본값이 많은 함수에서 특히 쓸모가 있습니다. 공식 코드는 `PrintFormat`의 남은 `param` 매개변수를 건너뛰고 로그 수준만 정할 때 `level:`을 붙입니다.

```enforce
PrintFormat("Player %1 joined", playerId, level: LogLevel.VERBOSE);
```

### out과 inout

엔진 문서는 `out`을 "함수 호출로 바뀔 변수", `inout`을 "함수가 먼저 읽고 나서 바꿀 변수"라고 설명합니다. 두 수식어를 붙인 매개변수는 참조로 전달되므로, 함수 안에서 대입한 값이 호출한 쪽의 변수에 남습니다. 함수 하나로 값을 여러 개 돌려줄 때 씁니다.

```enforce title="Scripts/Game/TAG_Stats.c"
class TAG_Stats
{
	//------------------------------------------------------------------------------------------------
	//! 배열의 최솟값과 최댓값을 구합니다. 배열이 비어 있으면 false를 돌려줍니다.
	static bool GetMinMax(notnull array<int> values, out int minValue, out int maxValue)
	{
		if (values.IsEmpty())
			return false;

		minValue = values[0];
		maxValue = values[0];
		foreach (int value : values)
		{
			if (value < minValue)
				minValue = value;

			if (value > maxValue)
				maxValue = value;
		}

		return true;
	}

	//------------------------------------------------------------------------------------------------
	//! score에서 penalty를 빼되 0 아래로는 내려가지 않게 합니다.
	static void ApplyPenalty(inout int score, int penalty)
	{
		score -= penalty;
		if (score < 0)
			score = 0;
	}
}
```

호출하는 쪽은 변수를 그대로 넘깁니다. C#과 달리 호출하는 쪽에는 `out`을 쓰지 않으며, 공식 코드도 `m_Group.GetCallsigns(company, platoon, squad, character, format);`처럼 변수만 넘깁니다.

```enforce
array<int> scores = { 40, 95, 12, 70 };
int lowest, highest;
if (TAG_Stats.GetMinMax(scores, lowest, highest))
	PrintFormat("min %1, max %2", lowest, highest);    // min 12, max 95

int score = 30;
TAG_Stats.ApplyPenalty(score, 50);                   // score는 0
```

성공 여부를 `bool`로 돌려주고 결과는 `out`으로 넘기는 형태는 공식 API에서도 자주 봅니다. 맵에서 값을 찾는 `map.Find(TKey key, out TValue val)`, 열거형의 최솟값과 최댓값을 구하는 `SCR_Enum.GetRange(typename enumType, out int min, out int max)`가 그 예입니다. 2장의 `string.ToInt(..., out int parsed)`도 `out`을 쓰지만, 반환값은 변환한 정수이고 `parsed`에는 읽은 글자 수가 들어갑니다.

배열을 채워 돌려줄 때는 호출하는 쪽이 빈 배열을 만들어 넘기고, 함수가 그 배열에 원소를 넣는 형태를 씁니다. 다음은 게임 모듈의 `SCR_Enum.GetEnumNames`를 쓰는 예입니다.

```enforce
// static int GetEnumNames(typename enumType, out notnull array<string> stringValues)
array<string> names = {};
SCR_Enum.GetEnumNames(TAG_EWeather, names);    // names에 열거형 값 이름이 채워짐
```

### notnull

`notnull`은 객체 매개변수가 `null`이면 안 된다는 표시입니다. 위키에 따르면 `null`을 넘기면 가상 머신 예외가 나고 메서드는 실행되지 않습니다. 그래서 메서드 안에서는 `null` 검사 없이 바로 쓸 수 있습니다.

```enforce
static void Describe(notnull IEntity entity)
{
	Print("Entity: " + entity.GetName());    // null 검사 없이 바로 씀
}
```

`notnull`이 `null`을 막아 주는 것은 아닙니다. 책임을 호출하는 쪽에 넘길 뿐이므로, 값이 `null`일 수 있다면 부르기 전에 검사합니다.

```enforce
if (entity)
	Describe(entity);
```

### const 매개변수와 가변 인수

공식 코드에는 `private vector GetRandomPositionOnEntity(const IEntity entity)`처럼 `const`를 붙인 매개변수도 있습니다. 함수 안에서 바꾸지 않을 매개변수임을 표시하는 용도입니다. 객체에 붙인 `const`는 2장에서 본 것처럼 참조만 고정합니다.

엔진 문서는 매개변수의 개수와 타입이 고정되어 있으며 가변 인수(variadic parameter)는 없다고 밝힙니다. `PrintFormat`이 인수를 아홉 개까지 받는 것은 기본값이 `NULL`인 매개변수 아홉 개를 미리 선언해 두었기 때문입니다. 개수가 정해지지 않은 값을 넘기려면 배열을 씁니다.

## 오버로드

같은 이름의 함수를 매개변수 목록만 다르게 여러 개 선언하는 것을 **오버로드**(overload)라고 합니다. Python과 JavaScript에는 없는 기능이지만 Enforce Script에서는 클래스의 메서드에 쓸 수 있고, 공식 코드에서도 흔히 씁니다.

| 공식 클래스 | 오버로드된 메서드 |
|---|---|
| `SCR_ChimeraAIAgent` | `bool IsEnemy(IEntity entity)`, `bool IsEnemy(Faction otherFaction)` |
| `SCR_AICombatMoveState` | `bool IsMoving()`, `bool IsMoving(SCR_EAICombatMoveReason eReason)` |
| `SCR_CameraPostProcessEffect` | `void SetMaterial()`, `void SetMaterial(ResourceName material)` |
| `SCR_Enum` | `static string GetDefault(int enumValue)`, `static string GetDefault(typename enumType)` |

매개변수의 개수가 다르거나, 같은 자리의 타입이 서로 관계없는 클래스처럼 분명히 다른 경우입니다. 공식 `IsEnemy(IEntity entity)`는 엔티티에서 진영을 구한 뒤 `IsEnemy(otherFaction)`을 다시 부르는데, 이처럼 한 오버로드가 다른 오버로드에 일을 넘기면 중복 코드가 줄어듭니다.

```enforce title="Scripts/Game/TAG_Logger.c"
class TAG_Logger
{
	//------------------------------------------------------------------------------------------------
	static void Log(string message)
	{
		Print("[TAG] " + message);
	}

	//------------------------------------------------------------------------------------------------
	static void Log(string message, int value)
	{
		Log(message + ": " + value);          // 다른 오버로드에 일을 넘김
	}

	//------------------------------------------------------------------------------------------------
	static void Log(string message, IEntity entity)
	{
		string entityName = "null";
		if (entity)
			entityName = entity.GetName();

		Log(message + ": " + entityName);
	}
}
```

`TAG_Logger.Log("Kills", 3);`을 실행하면 `[TAG] Kills: 3`이 출력됩니다.

<Tip title="오버로드를 안전하게 쓰는 기준">

- 공식 코드처럼 매개변수 개수가 다르거나, 같은 자리의 타입이 분명히 다른 오버로드만 만듭니다.
- 기본값이 있는 매개변수와 오버로드를 섞으면 어느 함수가 불릴지 읽는 사람이 헷갈립니다. 둘 중 하나만 씁니다.
- 공식 스크립트에서 오버로드는 클래스의 메서드에만 보이고 전역 함수에는 없습니다. 이 책도 메서드에서만 씁니다.
- 부모 클래스의 메서드를 다시 정의하는 오버라이드(override)는 오버로드와 다른 기능입니다(6장).

</Tip>

## 전역 함수, 메서드, 정적 메서드

함수는 놓이는 자리에 따라 세 가지로 나눌 수 있습니다.

- **전역 함수**: 클래스 밖에 선언한 함수입니다. 1장의 `Print`, `PrintFormat`과 2장에서 본 공식 `GetGame()`이 전역 함수입니다.
- **메서드**: 클래스 안에 선언한 함수입니다. 객체를 만든 뒤 `객체.메서드()`로 부릅니다(5장).
- **정적 메서드**: `static`을 붙인 메서드입니다. 엔진 문서에 따르면 객체 없이 `클래스이름.메서드이름()`으로 부를 수 있고, 정적 메서드 안에서는 정적 멤버만 쓸 수 있습니다.

공식 컨벤션은 전역 함수에도 태그를 붙이라고 정하면서, 전역 함수는 `modded`로 바꿀 클래스가 없으므로 꼭 필요할 때만 쓰라고 권합니다(12장). 그래서 이 책은 공용 함수를 `TAG_MathUtils` 같은 클래스의 정적 메서드로 모읍니다. 공식 코드의 `SCR_Enum`도 같은 방식입니다.

## 재귀

함수가 자기 자신을 부르는 것을 **재귀**(recursion)라고 합니다. 재귀 함수에는 더 이상 자신을 부르지 않고 끝나는 **기저 조건**(base case)이 반드시 있어야 합니다.

```enforce
//! n! = n × (n-1) × ... × 1
static int Factorial(int n)
{
	if (n <= 1)
		return 1;                   // 기저 조건

	return n * Factorial(n - 1);    // 자신을 다시 부름
}
```

`Factorial(5)`는 120입니다. `int`의 최댓값은 2,147,483,647이므로 13!(6,227,020,800)부터는 `int`에 담을 수 없다는 점도 기억해 둡니다.

게임 코드에서는 엔티티 계층처럼 나무 모양 구조를 훑을 때 재귀를 씁니다. 다음 예제는 3장에서 본 `GetChildren()`과 `GetSibling()`으로 모든 자손을 셉니다. 공식 `SCR_AIUtils.c`의 `FindComponentsInAllChildren`도 같은 구조이며, `depth`와 `maxDepth` 매개변수로 너무 깊이 내려가지 않게 막습니다. 예제도 그 방식을 따릅니다.

```enforce title="Scripts/Game/TAG_HierarchyUtils.c"
class TAG_HierarchyUtils
{
	//------------------------------------------------------------------------------------------------
	//! entity 아래의 모든 자손(자식, 손자, ...) 수를 셉니다.
	static int CountDescendants(notnull IEntity entity, int depth = 0, int maxDepth = 16)
	{
		if (depth >= maxDepth)
			return 0;                         // 너무 깊으면 더 내려가지 않음

		int count;
		IEntity child = entity.GetChildren();
		while (child)
		{
			count += 1 + CountDescendants(child, depth + 1, maxDepth);
			child = child.GetSibling();
		}

		return count;
	}
}
```

호출하는 쪽은 `CountDescendants(vehicle)`처럼 엔티티만 넘기고, `depth`와 `maxDepth`는 기본값에 맡깁니다. 기본값이 재귀의 시작값 역할을 하는 셈입니다.

## 함수를 값처럼 다루기: func 미리보기

### 메서드를 인수로 넘기기

엔진 API에는 함수를 인수로 받는 것이 많습니다. 함수를 나중에 대신 불러 달라고 맡기는 것이고, 이렇게 맡긴 함수를 **콜백**(callback)이라고 부릅니다. 매개변수 타입으로 쓰이는 것이 `Core/proto/Types.c`에 선언된 `func` 클래스입니다. 대표적인 예가 일정 시간 뒤에 함수를 불러 주는 콜 큐의 `CallLater`입니다.

```enforce
proto void CallLater(func fn, int delay = 0, bool repeat = false, void param1 = NULL,
	void param2 = NULL, void param3 = NULL, void param4 = NULL, void param5 = NULL,
	void param6 = NULL, void param7 = NULL, void param8 = NULL, void param9 = NULL);
```

`func` 자리에는 메서드 이름을 괄호 없이 씁니다. `delay`는 밀리초이고, `param1`부터는 그 메서드에 넘길 인수입니다.

```enforce
class TAG_DelayedMessage
{
	//------------------------------------------------------------------------------------------------
	void Schedule()
	{
		// 2000밀리초(2초) 뒤에 ShowMessage("Reinforcements arrived")를 한 번 부름
		GetGame().GetCallqueue().CallLater(ShowMessage, 2000, false, "Reinforcements arrived");
	}

	//------------------------------------------------------------------------------------------------
	protected void ShowMessage(string text)
	{
		Print(text);
	}
}
```

콜 큐의 자세한 쓰임, 반복 호출과 취소, 그때까지 객체가 살아 있어야 한다는 수명 문제는 11장에서 다룹니다.

### 콜백의 모양을 정하는 typedef func

엔진은 콜백이 어떤 모양이어야 하는지를 `typedef func`와 함수 선언으로 정해 둡니다. `Core/proto/EnWorld.c`에 있는 공식 선언은 다음과 같습니다.

```enforce
typedef func QueryEntitiesCallback;
bool QueryEntitiesCallback(IEntity e);
```

"`bool`을 돌려주고 `IEntity` 하나를 받는 함수"라는 모양에 `QueryEntitiesCallback`이라는 이름을 붙인 것입니다. 월드에서 구 안의 엔티티를 찾는 `BaseWorld.QueryEntitiesBySphere`가 이 타입의 콜백을 받습니다.

```enforce
proto external bool QueryEntitiesBySphere(vector center, float radius,
	QueryEntitiesCallback addEntity, QueryEntitiesCallback filterEntity = null,
	EQueryEntitiesFlags queryFlags = EQueryEntitiesFlags.ALL);
```

공식 문서에 따르면 `addEntity` 콜백은 찾은 엔티티마다 불리며, `true`를 돌려주면 검색을 계속하고 `false`를 돌려주면 멈춥니다. 다음 클래스는 반경 안의 엔티티 수를 셉니다.

```enforce title="Scripts/Game/TAG_NearbyCounter.c"
class TAG_NearbyCounter
{
	protected int m_iCount;

	//------------------------------------------------------------------------------------------------
	//! center에서 radius 미터 안에 있는 엔티티 수를 셉니다.
	int CountNear(vector center, float radius)
	{
		m_iCount = 0;

		World world = GetGame().GetWorld();
		if (!world)
			return 0;

		world.QueryEntitiesBySphere(center, radius, OnEntityFound);    // 메서드 이름을 넘김
		return m_iCount;
	}

	//------------------------------------------------------------------------------------------------
	//! QueryEntitiesCallback과 같은 모양: IEntity 하나를 받아 bool을 돌려줌
	protected bool OnEntityFound(IEntity entity)
	{
		m_iCount++;
		return true;    // 검색을 계속함
	}
}
```

<Compare title="콜백 안에서 바깥 값 쓰기">

```javascript
let count = 0;
world.query(center, radius, (entity) => { count++; return true; });
```

```enforce
// 람다가 없으므로 메서드를 넘기고, 결과는 멤버 변수에 모읍니다.
m_iCount = 0;
world.QueryEntitiesBySphere(center, radius, OnEntityFound);
```

</Compare>

Enforce Script의 문서와 공식 코드에는 람다나 익명 함수가 없습니다. 이름 있는 메서드를 넘기고, 콜백에서 모은 결과는 멤버 변수에 둡니다. 공식 `SCR_AIFindArsenalWithPrefab`도 콜백에서 찾은 엔티티를 멤버 배열에 모은 뒤 검색이 끝나면 그 배열을 읽습니다. 이벤트를 여러 구독자에게 알리는 `ScriptInvoker`는 11장에서 다룹니다.

## thread 키워드

엔진 문서는 스크립트가 협력형 멀티스레딩(cooperative multi-threading)을 지원하며, 이를 위한 명령이 `thread`, `Sleep`, `Wait` 세 가지라고 설명합니다. 메서드 호출 앞에 `thread`를 붙이면 그 메서드가 별도의 스크립트 스레드로 시작되고, `thread`는 메서드의 반환값이 아니라 스레드를 돌려줍니다. `Sleep(밀리초)`은 지정한 시간 동안, `Wait(조건)`은 조건이 참이 될 때까지 기다리며, 위키에 따르면 스레드로 실행 중인 메서드 안에서만 쓸 수 있습니다.

```enforce
class TAG_ThreadDemo
{
	//------------------------------------------------------------------------------------------------
	void MainMethod()
	{
		Print("MainMethod start");
		thread ThreadMethod();
		Print("MainMethod end");
	}

	//------------------------------------------------------------------------------------------------
	protected void ThreadMethod()
	{
		Print("ThreadMethod start");
		Sleep(500);
		Print("ThreadMethod end");
	}
}
```

위키에 따르면 `MainMethod()`는 다음 순서로 출력하고, 마지막 줄은 500밀리초 뒤에 나옵니다.

```text
MainMethod start
ThreadMethod start
MainMethod end
ThreadMethod end
```

이름과 달리 실제 운영체제 스레드가 아닙니다. 엔진 문서에 따르면 `Sleep`이나 `Wait`로 멈추기 전에는 다른 스레드로 넘어가지 않으며, 위키는 진짜 스레드가 아니므로 멤버 변수가 "스레드 안전"하다고 설명합니다.

<Warning title="게임 코드에서는 thread 대신 CallLater">

위키는 `thread`를 Workbench 플러그인에서 쓰고, 게임 안에서는 콜 큐의 `CallLater`를 쓰라고 안내합니다. 공식 스크립트에서도 `thread`는 Workbench 도구(`PeerTool.c`) 한 곳에서만 쓰입니다. 위키의 일부 예제는 메서드 이름을 `GetCallQueue()`로 적었지만, 1.8.0.13 공식 스크립트의 실제 이름은 `GetCallqueue()`입니다.

</Warning>

## 정리

<Summary>

- 함수는 `반환타입 이름(매개변수) { ... }`로 선언하고, 값이 없으면 반환 타입은 `void`입니다. `void`가 아닌 함수는 모든 경로에서 값을 돌려줍니다.
- 값 타입 인수는 복사되고 배열과 객체는 참조로 넘어갑니다. 값을 돌려받으려면 반환값이나 `out`, `inout` 매개변수를 씁니다. 호출하는 쪽에는 `out`을 쓰지 않습니다.
- 기본값은 매개변수 목록 뒤쪽에 두고, `매개변수이름: 값` 형태의 이름 있는 인수로 원하는 매개변수만 지정할 수 있습니다. 가변 인수는 없습니다.
- `notnull` 매개변수에 `null`을 넘기면 가상 머신 예외가 나고 메서드가 실행되지 않으므로, 호출하는 쪽에서 검사합니다.
- 메서드는 매개변수 개수나 타입을 달리해 오버로드할 수 있습니다. 공식 코드는 전역 함수를 오버로드하지 않습니다.
- 재귀 함수에는 기저 조건이 필요하며, 계층을 훑을 때는 최대 깊이도 함께 둡니다.
- 엔진 API는 `func` 타입으로 메서드를 받습니다. 람다가 없으므로 메서드 이름을 넘기고 결과는 멤버 변수에 모읍니다.
- `thread`는 협력형 스크립트 스레드이며 Workbench 플러그인용입니다. 게임 코드에서는 `GetGame().GetCallqueue().CallLater()`를 씁니다.

</Summary>
