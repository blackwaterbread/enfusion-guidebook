<Objectives>

- `if`/`else if`/`else`로 조건을 나누고, 객체와 문자열이 조건식에서 어떻게 판정되는지 설명할 수 있다.
- 조기 `return`과 짧은 회로 평가를 이용한 `null` 검사 관용구를 쓸 수 있다.
- `switch`에서 쓸 수 있는 값의 종류와 `break` 규칙을 알고 정수, 열거형, 문자열로 분기할 수 있다.
- `for`, `foreach`, `while`로 배열과 맵을 순회하고, `do-while`이 필요한 상황을 `while`로 바꿔 쓸 수 있다.
- `break`, `continue`, `return`으로 흐름을 끊고, 게임 코드에서 무한 루프가 위험한 이유를 설명할 수 있다.

</Objectives>

Enforce Script의 제어문은 C 계열 언어와 거의 같아서 문법 자체는 금방 익숙해집니다. 이 장에서는 문법보다 Python이나 JavaScript와 판정 방식이 다른 부분, 공식 코드가 즐겨 쓰는 관용구, 그리고 게임 엔진 안에서 반복문을 쓸 때 조심할 점에 집중합니다.

이 장의 짧은 예제도 메서드 본문의 일부입니다. 파일 경로가 붙은 예제는 그대로 저장해 컴파일한 뒤 Remote Console에서 정적 메서드를 불러 실행할 수 있습니다.

## if 문

### 기본 형태

`if` 뒤 괄호 안의 조건이 참이면 블록을 실행합니다. 조건을 더 나누려면 `else if`를, 나머지 경우는 `else`를 씁니다. Python의 `elif`처럼 줄여 쓰는 키워드는 없습니다.

```enforce
int health = 45;

if (health > 75)
{
	Print("Healthy");
}
else if (health > 25)
{
	Print("Injured");
}
else
{
	Print("Critical");
}
```

실행 결과는 다음과 같습니다.

```text
Injured
```

공식 컨벤션은 중괄호를 언제나 새 줄에 두는 Allman 스타일을 씁니다. 실행할 문장이 하나뿐이면 중괄호를 생략할 수 있으며, 공식 코드와 위키 예제도 `if (!entity) return;`처럼 짧은 조건에서는 중괄호 없이 씁니다. 다만 문장을 하나 더 넣을 때 중괄호를 빠뜨리기 쉬우니, 한 줄이라도 들여쓰기를 반드시 맞춥니다.

```enforce
if (health <= 0)
	return;            // 문장이 하나면 중괄호 없이 쓸 수 있음
```

### 조건식의 참과 거짓

조건식에는 보통 `bool`을 씁니다. 그 밖의 값도 조건식에 쓸 수 있는데, 위키와 엔진 문서가 정리한 판정 규칙은 다음과 같습니다.

| 조건식의 값 | 참으로 보는 경우 | 권장하는 표현 |
|---|---|---|
| `bool` | `true` | 그대로 씀 |
| 객체(배열, `map` 포함) | `null`이 아님 | `if (obj)` 또는 `if (obj != null)` |
| `int`, `float` | 0이 아님 | `if (count != 0)` |
| `string` | 비어 있지 않음 | `if (!text.IsEmpty())` |

위키는 `if (intValue)`나 `if (stringValue)`처럼 숫자와 문자열을 그대로 조건에 쓰는 것을 권하지 않습니다. 객체를 `if (obj)`로 검사하는 것은 공식 코드 전체에서 쓰는 표준 관용구입니다.

<Compare title="빈 배열은 참일까 거짓일까">

```python
items = []
if items:              # 빈 리스트는 거짓
    print("has items")
```

```enforce
array<string> items = {};
if (items)                        // null이 아니므로 참: 비어 있어도 들어옴
	Print("array exists");

if (items && !items.IsEmpty())    // 비어 있지 않은지는 따로 확인
	Print("has items");
```

</Compare>

공식 코드도 `if (!m_aBudgetsToEvaluate || m_aBudgetsToEvaluate.IsEmpty())`처럼 `null`과 빈 배열을 따로 검사합니다.

### null 검사 관용구

`null`인 객체의 메서드를 부르면 가상 머신 예외가 납니다. 공식 코드가 이를 막으려고 쓰는 방법은 크게 두 가지입니다.

- **조기 `return`(guard clause)**: 메서드 첫머리에서 `null`이면 바로 빠져나갑니다. 나머지 코드는 객체가 있다고 믿고 쓸 수 있어 중첩이 줄어듭니다.
- **짧은 회로 평가**: `&&`의 왼쪽이 거짓이면 오른쪽을 계산하지 않으므로 `if (parent && parent.GetName() == "Base")`처럼 검사와 사용을 한 줄에 씁니다(2장).

다음 예제는 엔티티(10장)의 이름과 부모 이름을 출력합니다. `IEntity`의 `GetName()`과 `GetParent()`는 공식 스크립트 `Core/generated/Entities/IEntity.c`에 선언된 메서드입니다.

```enforce title="Scripts/Game/TAG_EntityReporter.c"
class TAG_EntityReporter
{
	//------------------------------------------------------------------------------------------------
	//! 엔티티의 이름과 부모 엔티티의 이름을 출력합니다.
	static void Report(IEntity entity)
	{
		if (!entity)
		{
			Print("No entity", LogLevel.WARNING);
			return;                            // 조기 return
		}

		string entityName = entity.GetName();
		if (entityName.IsEmpty())
			entityName = "(unnamed)";

		IEntity parent = entity.GetParent();   // 부모가 없으면 null
		if (parent && !parent.GetName().IsEmpty())
			Print(entityName + " is attached to " + parent.GetName());
		else
			Print(entityName + " has no named parent");
	}
}
```

매개변수 자체가 `null`이면 안 되는 메서드라면 `notnull` 수식어로 호출하는 쪽에 책임을 넘길 수 있습니다(4장). 부모 타입 변수를 자식 타입으로 바꾸는 `Cast`의 결과도 실패하면 `null`이므로 같은 방식으로 검사합니다(6장).

## switch 문

### 형태와 쓸 수 있는 값

`switch`는 값 하나를 여러 `case`와 비교해 맞는 곳으로 이동합니다. 엔진 문서는 숫자, 상수, 문자열로 분기할 수 있다고 설명하며, 공식 코드에서는 정수, 열거형, 문자열 `switch`를 모두 볼 수 있습니다. 어느 `case`에도 맞지 않으면 `default`로 갑니다.

```enforce title="Scripts/Game/TAG_CommandHandler.c"
class TAG_CommandHandler
{
	//------------------------------------------------------------------------------------------------
	static void Handle(string command)
	{
		switch (command)
		{
			case "start":
			case "begin":                       // 여러 라벨이 같은 코드를 씀
				Print("Starting");
				break;

			case "stop":
				Print("Stopping");
				break;

			default:
				Print("Unknown command: " + command);
				break;
		}
	}
}
```

`TAG_CommandHandler.Handle("begin");`을 실행하면 `Starting`이, `Handle("jump");`를 실행하면 `Unknown command: jump`가 출력됩니다. 문자열 비교는 대소문자를 구분하므로 `"Start"`는 `default`로 갑니다.

### break와 fall-through

각 `case`의 코드는 `break`로 끝내야 `switch`를 빠져나갑니다. 메서드 안이라면 `return`으로 끝내도 됩니다. 위 예제처럼 코드가 없는 `case` 라벨을 연달아 쓰면 그 라벨들이 아래 코드를 함께 씁니다. 공식 코드도 `case EWeaponType.WT_ROCKETLAUNCHER:`와 `case EWeaponType.WT_GRENADELAUNCHER:`를 겹쳐 같은 처리를 하는 식으로 이 방법을 자주 씁니다.

코드가 있는 `case`에서 `break`를 빠뜨렸을 때의 동작은 공식 문서에 나와 있지 않습니다. 실제로 컴파일해 보면 위치에 따라 결과가 다릅니다. 그 `case`가 `switch`의 첫 번째 `case`이면 `Switch: fall through cases can't have a body`라는 컴파일 오류가 납니다. 두 번째 이후의 `case`이면 컴파일은 되고, C 언어처럼 다음 `case`의 코드까지 이어서 실행됩니다(fall-through). 공식 스크립트에도 두 번째 이후의 `case`에서 `break`가 빠진 곳이 있습니다. C#은 이런 코드를 모두 컴파일 오류로 막지만 Enforce Script는 첫 번째 `case`만 막으므로, 코드가 있는 `case`는 빠짐없이 `break`나 `return`으로 끝내세요.

<Pitfall title="break를 빠뜨린 case">

아래 예에서 첫 번째 `case`의 `break`를 빼면 컴파일 오류가 납니다. 두 번째 이후의 `case`에서 빼면 컴파일은 되지만 그 아래 `case`의 코드까지 실행되므로, 오류 없이 엉뚱한 메시지가 함께 출력됩니다.

```enforce
switch (alertLevel)
{
	case 1:
		Print("Yellow alert");
		break;    // [!code ++]

	case 2:
		Print("Red alert");
		break;
}
```

</Pitfall>

### case 안의 변수와 switch 뒤의 반환값

`case` 안에서 변수를 선언할 때는 공식 코드처럼 `case` 코드를 중괄호로 감싸 스코프를 분명히 해 두면 안전합니다. 또 값을 돌려주는 메서드가 `switch`로 끝날 때, 공식 코드는 모든 `case`가 `return`하더라도 `switch` 뒤에 `return`을 하나 더 둡니다. 다음 예제가 두 습관을 모두 보여 줍니다. `TAG_EWeather`는 2장의 열거형입니다.

```enforce title="Scripts/Game/TAG_WeatherRules.c"
class TAG_WeatherRules
{
	//------------------------------------------------------------------------------------------------
	//! 날씨에 따른 시야 거리(미터)
	static float GetViewDistance(TAG_EWeather weather)
	{
		switch (weather)
		{
			case TAG_EWeather.CLEAR:
				return 2000;

			case TAG_EWeather.CLOUDY:
				return 1500;

			case TAG_EWeather.RAIN:
			case TAG_EWeather.STORM:
			{
				float distance = 800;
				if (weather == TAG_EWeather.STORM)
					distance = distance * 0.5;

				return distance;
			}
		}

		return 1000;    // 모든 경로에서 값을 돌려주도록 switch 뒤에 둠
	}
}
```

<Note title="switch에서 쓰지 않는 값">

엔진 문서가 나열한 숫자, 상수, 문자열 말고 실수나 벡터로 분기하는 예는 문서에도 공식 코드에도 없습니다. 그런 값은 `if`/`else if`로 비교합니다. `case` 라벨에는 리터럴, 열거형 값, `const` 상수처럼 고정된 값을 씁니다.

</Note>

## 반복문

### for

`for`는 초기화, 조건, 갱신 세 부분으로 반복을 제어합니다. 조건이 참인 동안 블록을 실행하고, 블록이 끝날 때마다 갱신 부분을 실행합니다.

```enforce
for (int i = 0; i < 3; i++)
{
	Print("Step " + i);
}
```

실행 결과는 다음과 같습니다.

```text
Step 0
Step 1
Step 2
```

위키에 따르면 초기화 부분과 갱신 부분은 생략할 수 있습니다. 공식 Best Practices 문서는 배열을 인덱스로 돌 때 `Count()`를 매번 부르지 않도록 초기화 부분에서 한 번만 구해 두는 형태를 권합니다. `int i`는 선언만 해도 0이므로 `= 0`을 생략했습니다.

```enforce
array<string> names = { "Alpha", "Bravo", "Charlie" };
for (int i, count = names.Count(); i < count; i++)
{
	Print("#" + i + " " + names[i]);
}
```

뒤에서부터 돌 때는 `for (int i = names.Count() - 1; i >= 0; i--)`처럼 씁니다. 반복 중에 원소를 지우는 경우에 이 형태가 필요한데, 자세한 내용은 8장에서 다룹니다.

### foreach

처음부터 끝까지 모든 원소를 돌 때는 `foreach`가 간단합니다. Best Practices 문서도 처음부터 끝까지 순회할 때는 `foreach`가 더 빠르다고 설명합니다. 원소 타입과 변수 이름을 쓰고 콜론(`:`) 뒤에 컬렉션을 씁니다. 변수를 두 개 쓰면 배열에서는 인덱스와 값을 함께 받습니다.

```enforce
array<string> names = { "Alpha", "Bravo", "Charlie" };

foreach (string name : names)
{
	Print(name);
}

foreach (int index, string name : names)
{
	Print("#" + index + " " + name);
}
```

맵(map)에서는 변수 두 개가 키와 값이고, 변수 하나만 쓰면 값만 받습니다. 맵은 위키가 경고하듯 넣은 순서대로 저장되지 않으므로 순회 순서를 믿으면 안 됩니다.

```enforce
map<string, int> ammo = new map<string, int>();
ammo.Insert("rifle", 120);
ammo.Insert("pistol", 45);

foreach (string weapon, int rounds : ammo)
{
	Print(weapon + ": " + rounds);    // 순서는 보장되지 않음
}

int total;
foreach (int rounds : ammo)           // 값만 꺼낼 때
{
	total += rounds;
}
```

<Compare title="인덱스와 값을 함께 순회하기">

```python
for i, name in enumerate(names):
    print(i, name)
```

```javascript
for (const [i, name] of names.entries()) {
  console.log(i, name);
}
```

```enforce
foreach (int i, string name : names)
{
	Print("#" + i + " " + name);
}
```

</Compare>

정적 배열(`int values[5]`)도 `foreach`로 돌 수 있습니다. 배열, `set`, `map`의 메서드와 순회 중에 원소를 바꿀 때의 주의점은 8장에서 다룹니다.

### while

`while`은 조건이 참인 동안 블록을 반복합니다. 반복 횟수를 미리 알 수 없을 때 씁니다.

```enforce
int countdown = 3;
while (countdown > 0)
{
	Print("T-" + countdown);
	countdown--;
}
Print("Launch");
```

실행 결과는 다음과 같습니다.

```text
T-3
T-2
T-1
Launch
```

`while`의 조건에 객체를 그대로 쓰는 관용구도 공식 코드에 자주 나옵니다. 엔티티의 자식은 `GetChildren()`이 첫 번째 자식을, `GetSibling()`이 다음 형제를 돌려주며, 더 없으면 `null`을 돌려줍니다. 공식 `SCR_AIUtils.c`도 이 방법으로 자식 엔티티를 훑습니다.

```enforce
//! parent 바로 아래에 있는 자식 엔티티의 수를 셉니다.
static int CountChildren(notnull IEntity parent)
{
	int count;
	IEntity child = parent.GetChildren();    // 첫 번째 자식, 없으면 null
	while (child)                            // null이 되면 반복 끝
	{
		count++;
		child = child.GetSibling();          // 다음 형제, 없으면 null
	}

	return count;
}
```

### do-while이 필요할 때

엔진 문서와 위키가 소개하는 반복문은 `for`, `foreach`, `while` 세 가지이고, `do-while`은 문서에도 공식 스크립트에도 나오지 않습니다. 실제로 `do { … } while (…);`를 쓰면 구문 오류가 납니다. 본문을 적어도 한 번 실행한 뒤 조건을 검사하고 싶다면 `while (true)`와 `break`로 같은 흐름을 만듭니다. 이때 반드시 최대 반복 횟수 같은 안전장치를 함께 둡니다.

```enforce
int roll;
int tries;
while (true)
{
	roll = Math.RandomIntInclusive(1, 6);    // 1부터 6까지(양 끝 포함)
	tries++;

	if (roll == 6 || tries >= 20)            // 원하는 결과가 나오거나 20번이면 멈춤
		break;
}
PrintFormat("Rolled %1 after %2 tries", roll, tries);
```

## break, continue, return

### break와 continue

`break`는 가장 안쪽의 반복문이나 `switch`를 빠져나갑니다. `continue`는 이번 반복의 나머지를 건너뛰고 다음 반복으로 갑니다.

```enforce
array<int> damages = { 12, -3, 40, 0, 25 };

int total;
foreach (int damage : damages)
{
	if (damage <= 0)
		continue;         // 0 이하는 건너뜀

	total += damage;
}

int firstBig = -1;
foreach (int index, int damage : damages)
{
	if (damage >= 30)
	{
		firstBig = index;
		break;            // 찾았으면 더 볼 필요 없음
	}
}
PrintFormat("total %1, first big hit at %2", total, firstBig);
```

실행 결과는 `total 77, first big hit at 2`입니다. Best Practices 문서도 반복문 안에서 처리할 수 없는 원소는 `continue`로 일찍 건너뛰라고 권합니다.

### 중첩된 반복문 빠져나가기

`break`는 한 단계만 빠져나갑니다. Enforce Script의 문서와 키워드 목록에는 JavaScript의 레이블 `break`나 `goto` 같은 문법이 없으므로, 바깥 반복문까지 끝내려면 플래그 변수를 쓰거나 반복문을 메서드로 분리해 `return`합니다.

```enforce
bool found;
int foundRow = -1;
for (int row = 0; row < 3 && !found; row++)
{
	for (int col = 0; col < 3; col++)
	{
		if (row * col == 2)
		{
			found = true;      // 바깥 반복문의 조건이 이 값을 봄
			foundRow = row;
			break;             // 안쪽 반복문만 빠져나감
		}
	}
}
```

반복문을 메서드로 분리하면 찾는 즉시 `return`해서 모든 반복을 한 번에 끝낼 수 있어 더 깔끔합니다. 메서드의 반환값과 `out` 매개변수는 4장에서 다룹니다.

### 조기 return

`return`은 메서드를 즉시 끝냅니다. 처리할 수 없는 경우를 메서드 첫머리에서 먼저 걸러 내면, 정상 경로의 코드가 깊게 중첩되지 않습니다. 위키의 `return` 예제와 공식 코드 대부분이 이렇게 씁니다.

```enforce
//! 0으로 나누지 않는 평균 계산
static float Average(notnull array<int> values)
{
	if (values.IsEmpty())
		return 0;          // 처리할 수 없는 경우를 먼저 걸러 냄

	int sum;
	foreach (int value : values)
	{
		sum += value;
	}

	return (float)sum / values.Count();
}
```

## 게임 루프 안에서 무한 루프가 위험한 이유

엔진은 프레임마다 엔티티 이벤트나 콜백 같은 스크립트 코드를 부릅니다(10장, 11장). 엔진 문서에 따르면 스크립트의 멀티스레딩은 협력형이어서, 실행 중인 코드가 `Sleep`이나 `Wait`로 멈추기 전에는 다른 스크립트 스레드로 넘어가지 않습니다. 그래서 끝나지 않는 반복문은 다른 코드에 차례를 넘기지 않고, 위키의 경고처럼 프로그램 전체를 멈출 수 있습니다.

멈춘 상태가 오래가면 더 큰 문제가 됩니다. 명령줄 문서에 따르면 엔진에는 프리즈 감지 기능이 있어, 기본값인 300초 동안 응답이 없으면 게임은 강제로 크래시하고 Workbench는 미니덤프를 만든 뒤 기다립니다(`-freezeCheck`, `-freezeCheckMode`). 어느 쪽이든 테스트는 거기서 끝납니다.

흔한 원인은 반복 변수가 바뀌지 않는 경우입니다. 다음 코드는 `i`가 5가 되면 `continue`가 `i++`를 건너뛰므로 영원히 끝나지 않습니다.

```enforce
int i = 0;
while (i < 10)
{
	if (i == 5)
		continue;      // i가 더 이상 늘지 않음 // [!code highlight]

	Print("Value " + i);
	i++;
}
```

`for`로 바꾸면 갱신 부분 `i++`는 `continue` 뒤에도 실행되므로 이 문제가 사라집니다.

```enforce
for (int i = 0; i < 10; i++)
{
	if (i == 5)
		continue;      // for의 i++는 그대로 실행됨

	Print("Value " + i);
}
```

<Tip title="반복문 안전 점검">

- 반복할 때마다 조건이 끝을 향해 바뀌는지 확인합니다. 정해진 횟수라면 `while`보다 `for`나 `foreach`가 안전합니다.
- `while (true)`에는 언제나 최대 반복 횟수 같은 탈출 조건을 함께 둡니다.
- 계산량이 큰 일은 한 프레임에 몰아서 하지 말고 여러 프레임에 나눕니다. 공식 Performance 문서가 권하는 방법이며, 일정 시간마다 반복하는 일은 콜 큐의 `CallLater`로 처리합니다(11장).

</Tip>

## 정리

<Summary>

- `if`/`else if`/`else`로 조건을 나눕니다. 문장이 하나면 중괄호를 생략할 수 있지만 들여쓰기는 반드시 맞춥니다.
- 조건식에서 객체는 `null`이 아니면 참입니다. 배열도 객체라서 비어 있어도 참이므로, 빈 배열은 `IsEmpty()`로 따로 검사합니다.
- `null` 검사는 조기 `return`과 `&&`의 짧은 회로 평가로 씁니다.
- `switch`는 정수, 열거형, 문자열로 분기합니다. 각 `case`는 `break`나 `return`으로 끝내고, 코드 없는 라벨을 겹쳐 같은 처리를 공유합니다. 첫 번째 `case`에서 `break`를 빠뜨리면 컴파일 오류, 그 밖의 `case`에서는 다음 `case`까지 실행됩니다.
- 반복문은 `for`, `foreach`, `while`이 있습니다. `foreach (int i, T value : array)`로 인덱스를, `foreach (K key, V value : map)`으로 키를 함께 받습니다. 맵의 순회 순서는 보장되지 않습니다.
- `do-while`은 지원하지 않으므로(구문 오류) `while (true)`와 `break`, 안전장치로 대신합니다.
- 끝나지 않는 반복문은 게임 전체를 멈춥니다. 반복 변수가 끝을 향해 바뀌는지 확인하고, 무거운 일은 여러 프레임에 나눕니다.

</Summary>
