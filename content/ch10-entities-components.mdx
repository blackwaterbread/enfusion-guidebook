<Objectives>

- 엔티티, 컴포넌트, 프리팹이 각각 무엇이고 서로 어떻게 맞물리는지 설명할 수 있다.
- `ScriptComponent`와 짝 클래스(`...ComponentClass`)를 선언해 World Editor에서 붙일 수 있는 컴포넌트를 만들 수 있다.
- `OnPostInit`, `EOnInit`, `EOnFrame`, `OnDelete`가 언제 불리는지 알고 `SetEventMask`로 필요한 이벤트만 켤 수 있다.
- `[Attribute]`로 Workbench에 속성을 노출하고 `FindComponent`로 다른 컴포넌트를 찾을 수 있다.
- 프리팹으로 엔티티를 만들고 지우며, 위치·변환 행렬·부모와 자식 관계를 다룰 수 있다.

</Objectives>

1장부터 9장까지는 언어 자체를 배웠습니다. 이 장부터는 그 언어로 게임 엔진을 다룹니다. Arma Reforger의 월드에 있는 건물, 차량, 캐릭터는 물론이고 게임 규칙을 담당하는 게임 모드까지 모두 엔티티이며, 엔티티의 기능은 대부분 컴포넌트가 맡습니다. 모드를 만든다는 것은 대개 새 컴포넌트를 만들어 엔티티에 붙이거나, 기존 컴포넌트의 동작을 바꾸는 일입니다.

이 장의 내용은 이벤트와 타이머(11장), modded 클래스(12장), UI(13장), 리플리케이션(14장)의 바탕이 됩니다. 예제 파일은 모두 애드온의 `Scripts/Game` 폴더 아래에 둔다고 가정합니다.

## Enfusion의 월드 모델

### 엔티티

엔티티(entity)는 월드에 존재하는 객체의 기본 단위입니다. 스크립트에서 모든 엔티티의 뿌리는 `IEntity`(`Core/generated/Entities/IEntity.c`)이고, 스크립트로 새 엔티티 종류를 만들 때는 이를 상속한 `GenericEntity`(`GameLib`)를 부모로 씁니다.

엔티티는 위치와 방향, 즉 변환(transform)을 가지며 다른 엔티티의 자식이 되어 계층 구조를 이룰 수 있습니다. `IEntity`도 `Managed`를 상속하지만, 7장에서 설명했듯이 엔티티의 생성과 해제는 엔진이 관리합니다. 스크립트에서 `new`로 엔티티를 만들지 않고, 엔진 API로 생성을 요청합니다(이 장 뒷부분).

### 컴포넌트

컴포넌트(component)는 엔티티에 붙여 기능을 더하는 부품입니다. 엔진 쪽 컴포넌트의 부모는 `GenericComponent`이고, 스크립트로 만드는 컴포넌트는 이를 상속한 `ScriptComponent`(`GameLib/generated/Components/ScriptComponent.c`)를 부모로 씁니다. 컴포넌트는 언제나 어떤 엔티티에 속하며, 그 엔티티를 소유자(owner)라고 부릅니다. 위키는 컴포넌트가 엔티티 없이 존재할 수 없으므로 `GetOwner()`가 null을 돌려줄 일은 없다고 설명합니다.

하나의 엔티티에 여러 컴포넌트가 붙고, 각 컴포넌트는 자기 일만 합니다.

<Compare title="Unity의 컴포넌트와 비교">

C#으로 Unity를 써 봤다면 `MonoBehaviour`를 떠올리면 됩니다.

```csharp
public class Spinner : MonoBehaviour
{
    public float degreesPerSecond = 45f;   // Inspector에 노출

    void Update()                          // 매 프레임 자동 호출
    {
        transform.Rotate(0f, degreesPerSecond * Time.deltaTime, 0f);
    }
}
// 같은 GameObject의 다른 컴포넌트 찾기
var spinner = GetComponent<Spinner>();
```

Enforce Script도 구조는 같지만 세 가지가 다릅니다. 짝 클래스(`...Class`)가 따로 필요하고, 매 프레임 이벤트(`EOnFrame`)는 `SetEventMask`로 직접 켜야 하며, `FindComponent`는 `Managed`를 돌려주므로 형변환을 해야 합니다. 완성된 코드는 이 장에서 차례로 만들어 봅니다.

```enforce
TAG_SpinComponent spin = TAG_SpinComponent.Cast(owner.FindComponent(TAG_SpinComponent));
```

</Compare>

### 프리팹

프리팹(prefab)은 엔티티와 컴포넌트의 구성과 속성값을 파일 하나에 저장해 둔 틀입니다. World Editor는 프리팹을 틀로 삼아 인스턴스를 만듭니다. Prefabs Basics 문서에 따르면 엔티티 프리팹은 `.et`(Entity Template) 파일로, 계층을 이루는 여러 엔티티와 그 컴포넌트를 담을 수 있습니다. 프리팹은 다른 프리팹을 상속해 물려받은 값을 다시 정할 수 있고, 월드에 놓인 인스턴스에서도 값을 바꿀 수 있습니다. World Editor의 속성 창에서 이름이 굵게 표시된 속성이 그 단계에서 값을 바꾼 속성입니다.

프리팹 파일은 텍스트입니다. BaseContainer Usage 문서가 예로 든 나무 프리팹의 첫 줄은 다음과 같습니다. `Tree`는 클래스 이름이고, 따옴표 안은 부모 프리팹입니다.

```text
Tree : "{388AE316D09D0680}Prefabs/Vegetation/Core/Tree_Base.et" {
 // ...
}
```

어떤 단계에서 값을 정하지 않은 속성은 그 값을 정한 가장 가까운 조상에서 읽고, 아무 데서도 정하지 않았으면 기본값(스크립트의 어트리뷰트라면 뒤에서 볼 `[Attribute]`의 `defvalue`)이 됩니다. 따옴표 안의 `{388AE316D09D0680}`은 리소스를 구별하는 GUID이며, 이렇게 GUID와 경로를 붙여 쓴 문자열을 `ResourceName`이라고 합니다. 리소스와 GUID는 12장에서 자세히 다룹니다.

| 확장자 | 종류 | 여는 편집기 |
|---|---|---|
| `.et` | 엔티티 프리팹(Entity Template) | Workbench 메인 창의 프리팹 탭 |
| `.ct` | 컴포넌트 프리팹(Component Template) | Workbench 메인 창의 탭 |
| `.conf` | 설정 파일(config) | Workbench 메인 창의 탭 |
| `.ent` | 월드(World Scene) | World Editor |
| `.c` | Enforce Script 소스 | Script Editor |

## 첫 스크립트 컴포넌트 만들기

### 컴포넌트와 짝 클래스

가장 단순한 컴포넌트부터 만들어 봅시다. 초기화되면 로그에 한 줄을 남기는 컴포넌트입니다.

```enforce title="Scripts/Game/TAG_HelloComponent.c"
[ComponentEditorProps(category: "TAG/Tutorial", description: "초기화되면 로그를 남깁니다")]
class TAG_HelloComponentClass : ScriptComponentClass
{
}

class TAG_HelloComponent : ScriptComponent
{
	override void OnPostInit(IEntity owner)
	{
		Print("TAG_HelloComponent 초기화: " + owner.GetName());
	}
}
```

클래스가 두 개인 데 주목하세요. 컴포넌트에는 짝 클래스가 꼭 있어야 합니다. 짝 클래스가 없으면 World Editor에 보이지 않는 정도가 아니라 컴파일 오류(`Missing Component Class for 'TAG_HelloComponentClass' for Component 'TAG_HelloComponent'`)가 납니다. 위키의 Create a Component 문서가 정한 규칙은 다음과 같습니다.

- 컴포넌트 클래스 이름은 `Component`로 끝나고, 파일 이름도 클래스 이름과 같게 짓습니다.
- 짝 클래스의 이름은 정확히 "컴포넌트 이름 + `Class`"여야 합니다. 여기서는 `TAG_HelloComponentClass`입니다.
- 짝 클래스는 `ScriptComponentClass`를 상속하고, 보통 컴포넌트 바로 위에 둡니다.
- 스크립트 파일은 `Game` 모듈, 즉 `Scripts/Game` 아래에 있어야 합니다. 다른 곳에 두면 컴포넌트 목록에 나타나지 않습니다.

짝 클래스 위의 `[ComponentEditorProps(...)]`는 World Editor에 보여 줄 정보입니다. `Core/generated/Attributes/ComponentEditorProps.c`에 정의된 매개변수는 `category`, `description`, `color`, `visible`, `insertable`, `configRoot`, `icon`이고 모두 기본값이 있습니다. `category`는 **Add Component** 목록에서 이 컴포넌트가 들어갈 분류입니다. 위키에 따르면 `description`과 `configRoot`는 현재 쓰이지 않고 `color`와 `visible`은 경계 상자 표시에 관한 설정이라, 실제로는 `category`와 `description` 정도만 적습니다.

직접 붙여 보려면 `TAG_HelloComponent.c`를 `Scripts/Game`에 저장해 컴파일한 뒤, World Editor에서 월드를 열고 엔티티 하나에 `TAG_HelloComponent`(분류 `TAG/Tutorial`)를 추가한 다음 로그를 확인합니다. 붙이는 순간에도 메시지가 찍힐 수 있는 이유는 다음 절의 수명 주기 표에 있습니다.

### 이벤트 마스크와 매 프레임 처리

이번에는 엔티티를 계속 회전시키는 컴포넌트를 만들어 봅시다. 매 프레임 일을 하려면 `EOnFrame`을 오버라이드하고, `SetEventMask`로 `FRAME` 이벤트를 켜야 합니다.

```enforce title="Scripts/Game/TAG_SpinComponent.c"
[ComponentEditorProps(category: "TAG/Tutorial", description: "엔티티를 계속 회전시킵니다")]
class TAG_SpinComponentClass : ScriptComponentClass
{
}

class TAG_SpinComponent : ScriptComponent
{
	[Attribute(defvalue: "45", uiwidget: UIWidgets.Slider, desc: "초당 회전 각도", params: "-360 360 1")]
	protected float m_fDegreesPerSecond;

	override void OnPostInit(IEntity owner)
	{
		SetEventMask(owner, EntityEvent.FRAME);	// 이 줄이 없으면 EOnFrame이 불리지 않는다
	}

	override void EOnFrame(IEntity owner, float timeSlice)
	{
		vector angles = owner.GetYawPitchRoll();	// (요, 피치, 롤)
		angles[0] = angles[0] + m_fDegreesPerSecond * timeSlice;
		owner.SetYawPitchRoll(angles);
	}
}
```

`EOnFrame`의 `timeSlice`는 지난 프레임부터 흐른 시간이고 단위는 초입니다. 프레임마다 시간 간격이 다르므로, 움직임에 `timeSlice`를 곱해야 프레임률과 상관없이 같은 속도가 나옵니다. `vector`의 성분은 `angles[0]`처럼 인덱스로 읽고 쓸 수 있습니다(9장).

`SetEventMask`는 `GenericComponent`에 `SetEventMask(notnull IEntity owner, int mask)`로 정의되어 있습니다. 넘긴 비트를 기존 마스크에 OR로 더하므로 `EntityEvent.INIT | EntityEvent.FRAME`처럼 여러 이벤트를 한 번에 켤 수 있고, 끌 때는 `ClearEventMask(owner, mask)`를 씁니다. 이 함수의 공식 주석은 **컴포넌트 생성자에서 호출하면 부모 엔티티에 마스크가 제대로 설정되지 않는다**고 경고합니다. 그래서 공식 컴포넌트는 대부분 `OnPostInit`에서 호출합니다.

<Pitfall title="EOnFrame을 오버라이드했는데 불리지 않는다">

`EOn`으로 시작하는 이벤트는 마스크를 켜야만 불립니다. 오버라이드만 하고 `SetEventMask`를 빠뜨리는 것이 가장 흔한 실수입니다. 1.8.0.13에서 World Editor에 배치한 엔티티, 프리팹 인스턴스, Play 중 프리팹으로 만든 엔티티로 시험해 보면 생성자에서 켠 마스크로도 `OnPostInit`에서 켠 경우와 같은 횟수로 `EOnFrame`이 불렸습니다. 그래도 공식 주석이 생성자에서 켜지 말라고 경고하므로, 아래처럼 `OnPostInit`에서 켜세요.

```enforce
void TAG_SpinComponent(IEntityComponentSource src, IEntity ent, IEntity parent)
{
	SetEventMask(ent, EntityEvent.FRAME);	// [!code --]
}

override void OnPostInit(IEntity owner)
{
	SetEventMask(owner, EntityEvent.FRAME);	// [!code ++]
}
```

</Pitfall>

## 수명 주기

### 무엇이 언제 불리는가

엔진이 엔티티와 컴포넌트의 메서드를 부르는 순서를 위키의 Entity Lifecycle 문서대로 정리하면 다음과 같습니다. "편집 모드" 열은 World Editor에서 편집하는 중에도 불리는지를 뜻합니다.

| 단계 | 엔티티 | 컴포넌트 | 편집 모드 |
|---|---|---|---|
| 생성 | 생성자 | | 예 |
| | | 생성자 | 예 |
| | | `OnPostInit` | 예 |
| | | `EOnInit` | 예 |
| | `EOnInit` | | 예 |
| 시뮬레이션 시작 | `EOnActivate` | | 아니요 |
| 시뮬레이션 반복 | `EOnFrame`, `EOnFixedFrame` 등 | `EOnFrame`, `EOnFixedFrame` 등 | 아니요 |
| 삭제 | | `OnDelete` | 예 |
| | 소멸자 | | 예 |
| | | 소멸자 | 예 |

여기서 두 가지를 기억해 두세요. 첫째, **`OnPostInit`과 `EOnInit`은 World Editor 편집 중에도 불립니다.** 앞의 실습에서 컴포넌트를 붙이자마자 메시지가 찍힌 이유입니다. 게임 중에만 해야 하는 일이라면 공식 코드처럼 `SCR_Global.IsEditMode(owner)`나 `GetGame().InPlayMode()`로 걸러 냅니다. 둘째, 위키는 **컴포넌트 소멸자에서 소유 엔티티를 건드리지 말라**고 경고합니다. 그때는 엔티티가 이미 지워진 뒤입니다. 정리 작업은 `OnDelete`에서 합니다.

### 주요 이벤트 메서드

`ScriptComponent`의 이벤트는 모두 `event protected`로 선언되어 있고(`RplSave`·`RplLoad`만 `bool`을 돌려주고 나머지는 `void`입니다), 자식 클래스에서 `override`로 다시 정의합니다. 공식 코드는 대부분 `override void OnPostInit(IEntity owner)`처럼 접근 제한자 없이 씁니다. 자주 쓰는 것만 추리면 다음과 같습니다.

| 메서드 | 불리는 때 | 켜야 할 마스크 |
|---|---|---|
| `OnPostInit(IEntity owner)` | 엔티티의 모든 컴포넌트가 초기화된 뒤 | 없음 |
| `EOnInit(IEntity owner)` | 엔티티가 할당·초기화된 뒤 | `EntityEvent.INIT` |
| `EOnFrame(IEntity owner, float timeSlice)` | 매 프레임 | `EntityEvent.FRAME` |
| `EOnPostFrame(IEntity owner, float timeSlice)` | 매 프레임, 물리 갱신 뒤 | `EntityEvent.POSTFRAME` |
| `EOnFixedFrame(IEntity owner, float timeSlice)` | 고정 주기(초당 30회) | `EntityEvent.FIXEDFRAME` |
| `EOnActivate(IEntity owner)` / `EOnDeactivate(IEntity owner)` | 컴포넌트가 활성화·비활성화될 때 | 없음 |
| `OnDelete(IEntity owner)` | 엔티티나 컴포넌트가 지워지기 직전 | 없음 |

`OnPostInit`은 같은 엔티티의 다른 컴포넌트가 모두 만들어진 뒤에 불리므로, 다른 컴포넌트를 찾아 저장해 두기에 알맞은 곳입니다. `EOnInit`이 필요하면 `OnPostInit`에서 `INIT` 마스크를 켜는 것이 공식 코드의 관용구입니다. 공식 `SCR_BaseLockComponent`는 `EOnInit`에서 할 일을 마친 뒤 `ClearEventMask(owner, EntityEvent.INIT)`로 마스크를 다시 끕니다.

### 활성 상태와 FRAME 이벤트

Entity Activeness 문서에 따르면 `FRAME` 이벤트를 켠 컴포넌트가 있으면 그 엔티티는 매 프레임 시뮬레이션 대상이 됩니다. 매 프레임 처리는 공짜가 아니므로 할 일이 없을 때는 마스크를 꺼 둡니다. 같은 문서는 0.9.8부터 컴포넌트가 기본으로 활성 상태이므로, 소유 엔티티에 `EntityFlags.ACTIVE`를 켜는 옛 방식 대신 `EOnActivate`에서 `SetEventMask`, `EOnDeactivate`에서 `ClearEventMask`를 호출해 각 컴포넌트가 자기 마스크를 관리하라고 권합니다. 다만 같은 이유로 엔티티가 스폰될 때는 컴포넌트의 `EOnActivate`가 불리지 않으므로, 처음 마스크는 문서의 예제처럼 `OnPostInit`에서 켭니다. 컴포넌트를 켜고 끄는 메서드는 `GenericComponent`의 `Activate(IEntity owner)`, `Deactivate(IEntity owner)`, `IsActive()`입니다.

## [Attribute]로 속성 노출하기

### Attribute의 매개변수

멤버 변수 위에 `[Attribute(...)]`를 붙이면 World Editor의 속성 창에서 값을 고칠 수 있고, 엔진은 인스턴스를 만들 때 저장된 값을 변수에 채워 줍니다. `Core/generated/Attributes/Attribute.c`의 생성자는 다음과 같습니다.

```enforce
void Attribute(string defvalue = "", string uiwidget = "auto", string desc = "",
	string params = "", ParamEnumArray enums = NULL, string category = "",
	int precision = 3, typename enumType = void, bool prefabbed = false)
```

모든 매개변수에 기본값이 있으므로 필요한 것만 이름 있는 인수(named argument)로 적는 방식이 공식 코드에 흔합니다. 앞의 몇 개는 순서대로 적고 나머지에만 이름을 붙이기도 합니다. `defvalue`는 타입과 상관없이 **언제나 문자열**입니다. `bool`은 `"0"`과 `"1"`, 숫자는 `"12.5"`, `vector`는 `"0 1 0"`처럼 씁니다.

| 매개변수 | 뜻 |
|---|---|
| `defvalue` | 기본값(문자열) |
| `uiwidget` | 편집 UI의 종류. `UIWidgets` 클래스의 상수를 씀. 생략하면 타입에 맞게 자동 선택 |
| `desc` | 속성 이름에 마우스를 올리면 보이는 설명 |
| `params` | UI별 설정. 숫자는 `"최솟값 최댓값 간격"`, 리소스는 확장자(`"et"`, `"conf class=클래스"`) |
| `enums` | 콤보 상자에 보일 항목 목록(`ParamEnumArray`) |
| `category` | 속성 창에서 묶어 보일 분류 이름 |

자주 쓰는 `UIWidgets` 상수는 `Core/attributes.c`에 정의되어 있습니다.

| 상수 | 용도 |
|---|---|
| `UIWidgets.Auto` | 변수 타입에 맞게 자동 선택(기본값) |
| `UIWidgets.CheckBox` | `bool` 체크 상자 |
| `UIWidgets.EditBox`, `UIWidgets.SpinBox`, `UIWidgets.Slider` | 숫자·문자열 입력, 숫자 위아래 버튼, 슬라이더 |
| `UIWidgets.ComboBox` | 목록에서 하나 고르기 |
| `UIWidgets.ColorPicker` | `Color` 색 고르기 |
| `UIWidgets.ResourceNamePicker`, `UIWidgets.ResourcePickerThumbnail` | `ResourceName` 리소스 고르기 |
| `UIWidgets.Object` | 설정 객체 하나 또는 배열(12장) |
| `UIWidgets.LocaleEditBox` | 로컬라이즈 문자열(13장) |

### 속성을 갖춘 컴포넌트

앞의 회전 컴포넌트에 속성을 몇 개 더 붙이고, 다른 코드가 회전을 켜고 끌 수 있는 공개 메서드 `SetSpinning()`도 만들어 봅시다. 회전 축은 열거형으로 고르게 합니다. 열거형을 콤보 상자로 보일 때는 `ParamEnumArray.FromEnum()`으로 항목 목록을 만드는 것이 공식 코드에서 가장 흔한 방법입니다.

```enforce
enum TAG_ESpinAxis
{
	YAW,
	PITCH,
	ROLL
}
```

이 열거형을 쓰는 컴포넌트 본체는 다음과 같습니다. 짝 클래스는 앞의 예제와 같으므로 생략했습니다.

```enforce title="Scripts/Game/TAG_SpinComponent.c"
class TAG_SpinComponent : ScriptComponent
{
	[Attribute(defvalue: "45", uiwidget: UIWidgets.Slider, desc: "초당 회전 각도",
		params: "-360 360 1", category: "Spin")]
	protected float m_fDegreesPerSecond;

	[Attribute(defvalue: "0", uiwidget: UIWidgets.ComboBox, desc: "회전 축",
		enums: ParamEnumArray.FromEnum(TAG_ESpinAxis), category: "Spin")]
	protected TAG_ESpinAxis m_eAxis;

	[Attribute(defvalue: "1", desc: "처음부터 회전할지 여부", category: "Spin")]
	protected bool m_bSpinOnStart;

	void SetSpinning(bool spinning)
	{
		if (spinning)
			SetEventMask(GetOwner(), EntityEvent.FRAME);
		else
			ClearEventMask(GetOwner(), EntityEvent.FRAME);	// 쉬는 동안은 프레임 이벤트를 끈다
	}

	override void EOnFrame(IEntity owner, float timeSlice)
	{
		int axis = m_eAxis;							// 0: 요, 1: 피치, 2: 롤
		vector angles = owner.GetYawPitchRoll();
		angles[axis] = angles[axis] + m_fDegreesPerSecond * timeSlice;
		owner.SetYawPitchRoll(angles);
	}

	override void OnPostInit(IEntity owner)
	{
		if (m_bSpinOnStart)
			SetSpinning(true);
	}
}
```

`m_bSpinOnStart`는 `uiwidget`을 생략했으므로 타입에 맞는 편집 UI가 자동으로 쓰입니다. 위키의 Config Object 문서에 따르면 `bool`은 체크 상자, `int`는 스핀 상자, `float`와 `string`은 편집 상자, `vector`는 좌표 입력, `Color`는 색 선택기, `ResourceName`은 리소스 선택기가 됩니다. 같은 문서는 속성 이름을 `m_`과 타입 접두사를 떼고 대문자 위치에서 나눠 보여 준다고 설명합니다(`m_iMyVariable`은 "My Variable").

### 프리팹 데이터: 인스턴스가 공유하는 값

어트리뷰트를 **짝 클래스**에 선언하면 그 값은 같은 프리팹의 인스턴스가 함께 쓰는 프리팹 데이터(Prefab Data)가 됩니다. 다만 1.8.0.13 Workbench에서 시험해 보면, 값을 바꾸지 않은 인스턴스끼리는 같은 프리팹 데이터를 쓰지만 World Editor에서 값을 바꾼 인스턴스는 컴포넌트의 값을 바꿨든 짝 클래스의 값을 바꿨든 프리팹 데이터를 따로 가졌습니다. 그래서 짝 클래스의 값도 인스턴스마다 다르게 정할 수 있습니다. 위키의 Prefab Data 문서는 최대 체력처럼 인스턴스마다 다를 필요가 없는 값을 예로 들며, 인스턴스가 많을수록 메모리를 아낄 수 있지만 읽을 때마다 가져와 형변환하는 비용이 드니 매 프레임 읽는 값이라면 따져 보라고 권합니다.

```enforce
class TAG_SpinComponentClass : ScriptComponentClass
{
	[Attribute(defvalue: "1", desc: "이 프리팹의 모든 인스턴스에 적용할 속도 배율")]
	protected float m_fSpeedMultiplier;

	float GetSpeedMultiplier()
	{
		return m_fSpeedMultiplier;
	}
}

// TAG_SpinComponent 안에서
float speed = m_fDegreesPerSecond;
TAG_SpinComponentClass prefabData = TAG_SpinComponentClass.Cast(GetComponentData(GetOwner()));
if (prefabData)
	speed *= prefabData.GetSpeedMultiplier();
```

`GetComponentData()`는 `GenericComponent`의 메서드로, 짝 클래스의 인스턴스를 `EntityComponentPrefabData` 타입으로 돌려줍니다. 공식 `SCR_FlagComponent`가 정확히 이 방식을 씁니다. 엔티티라면 `GetPrefabData()`를 같은 방식으로 형변환합니다.

## 다른 컴포넌트 찾기

### FindComponent와 형변환

같은 엔티티에 붙은 다른 컴포넌트는 `IEntity`의 `FindComponent(typename)`으로 찾습니다. 반환 타입이 `Managed`이므로 6장에서 배운 `Cast()`로 원하는 타입으로 바꾸고, 없을 수도 있으니 null을 검사합니다.

```enforce
// 엔티티에서 회전을 멈춘다. 회전 컴포넌트가 없으면 아무 일도 하지 않는다.
void TAG_StopSpinning(IEntity entity)
{
	TAG_SpinComponent spin = TAG_SpinComponent.Cast(entity.FindComponent(TAG_SpinComponent));
	if (!spin)
		return;

	spin.SetSpinning(false);	// TAG_SpinComponent에 만들어 둔 공개 메서드
}
```

같은 타입의 컴포넌트가 여러 개일 수 있다면 `FindComponents(typename typeName, notnull array<Managed> outComponents)`로 배열에 모두 받습니다. 반환값은 찾은 개수이고, 원소는 역시 하나씩 형변환해서 씁니다.

### 찾은 컴포넌트는 저장해 둔다

`FindComponent`는 엔티티의 컴포넌트 목록을 뒤지는 호출이므로 매 프레임 부르지 말고 `OnPostInit`에서 한 번 찾아 멤버 변수에 저장해 둡니다. 컴포넌트의 수명은 엔티티가 관리하므로 이런 멤버에는 `ref`를 붙이지 않습니다(7장). 꼭 함께 있어야 하는 컴포넌트가 있다면, `ScriptComponentClass`의 주석이 안내하는 대로 짝 클래스에서 정적 메서드 `Requires(IEntityComponentSource src)`를 오버라이드해 필요한 타입 목록을 돌려줄 수도 있습니다.

```enforce
[ComponentEditorProps(category: "TAG/Tutorial", description: "같은 엔티티의 회전 컴포넌트를 찾아 둡니다")]
class TAG_SpinSoundComponentClass : ScriptComponentClass
{
}

class TAG_SpinSoundComponent : ScriptComponent
{
	protected TAG_SpinComponent m_Spin;	// 약한 참조로 충분하다

	override void OnPostInit(IEntity owner)
	{
		m_Spin = TAG_SpinComponent.Cast(owner.FindComponent(TAG_SpinComponent));
		if (!m_Spin)
			Print("TAG_SpinSoundComponent: TAG_SpinComponent가 없습니다", LogLevel.WARNING);
	}
}
```

## 엔티티 만들고 지우기

### 프리팹에서 엔티티 만들기

실행 중에 엔티티를 만들 때는 프리팹 리소스를 불러와 `SpawnEntityPrefab`에 넘깁니다. 순서는 세 단계입니다.

1. `Resource.Load(ResourceName)`로 프리팹을 불러오고 `IsValid()`로 확인합니다.
2. `EntitySpawnParams`에 위치와 방향을 담습니다.
3. `GetGame().SpawnEntityPrefab(resource, world, params)`를 호출합니다.

```enforce
[ComponentEditorProps(category: "TAG/Tutorial", description: "프리팹으로 엔티티를 만듭니다")]
class TAG_SpawnerComponentClass : ScriptComponentClass
{
}

class TAG_SpawnerComponent : ScriptComponent
{
	[Attribute("", UIWidgets.ResourceNamePicker, desc: "생성할 프리팹", params: "et")]
	protected ResourceName m_sPrefab;

	//! position(월드 좌표)에 프리팹을 하나 만든다. 실패하면 null.
	IEntity SpawnAt(vector position)
	{
		Resource resource = Resource.Load(m_sPrefab);
		if (!resource || !resource.IsValid())
			return null;

		EntitySpawnParams params = new EntitySpawnParams();
		params.TransformMode = ETransformMode.WORLD;
		params.Transform[3] = position;	// 변환 행렬의 [3]이 위치(뒤에서 설명)

		return GetGame().SpawnEntityPrefab(resource, GetOwner().GetWorld(), params);
	}
}
```

`params: "et"`는 리소스 선택기에서 `.et` 파일만 보이게 합니다. `EntitySpawnParams`(`GameLib/gameLib.c`)의 필드는 다음과 같습니다.

| 필드 | 뜻 | 기본값 |
|---|---|---|
| `TransformMode` | `ETransformMode.WORLD`, `LOCAL`, `OFFSET` 가운데 하나 | `LOCAL` |
| `Transform[4]` | 변환 행렬 | 단위 행렬 |
| `Parent` | 부모로 붙일 엔티티 | null |
| `Scale` | 크기 배율 | 1 |

기존 엔티티와 같은 위치·방향으로 만들고 싶으면 `GetOwner().GetTransform(params.Transform);`처럼 행렬을 통째로 채우는 방법도 공식 코드에 자주 나옵니다.

<Warning title="프리팹 생성은 기본적으로 서버에서만">

엔진 문서 Loadtime and Runtime에 따르면 Arma Reforger는 클라이언트에서 실수로 엔티티가 생기는 일을 막으려고 기본적으로 프리팹 생성을 서버에서만 허용합니다. 클라이언트에만 있어도 되는 엔티티는 `SpawnEntityPrefabLocal()`로 만듭니다. 어느 쪽에서 실행 중인지 판단하는 방법과 생성한 엔티티의 복제는 14장에서 다룹니다.

</Warning>

### 엔티티 지우기

엔티티를 지울 때는 공식 헬퍼 `SCR_EntityHelper.DeleteEntityAndChildren(entity)`를 씁니다. 이름처럼 자식까지 함께 지우며, 내부에서 `RplComponent.DeleteRplEntity(entity, false)`를 호출하므로 리플리케이션되는 엔티티도 올바르게 처리합니다. 다음은 일정 시간이 지나면 소유 엔티티를 지우는 공식 `SCR_LifetimeComponent`입니다(메서드 사이의 구분선 주석만 뺐습니다).

```enforce
[ComponentEditorProps(category: "GameScripted", description: "")]
class SCR_LifetimeComponentClass : ScriptComponentClass
{
}

//! Delete entity after given duration.
class SCR_LifetimeComponent : ScriptComponent
{
	[Attribute(defvalue: "1")]
	protected float m_fLifeTime;

	override void EOnFrame(IEntity owner, float timeSlice)
	{
		if (m_fLifeTime < 0)
		{
			SCR_EntityHelper.DeleteEntityAndChildren(owner);
			return;
		}
		m_fLifeTime -= timeSlice;
	}

	override void OnPostInit(IEntity owner)
	{
		SetEventMask(owner, EntityEvent.FRAME);
	}
}
```

`IEntity.IsDeleted()`의 주석은 지워진 엔티티의 포인터가 그 프레임이 끝날 때까지 유효하다고 적습니다. 그런데 1.8.0.13 싱글플레이에서 실행 중에 만든 엔티티를 `SCR_EntityHelper.DeleteEntityAndChildren`으로 지워 보면, 다른 엔티티의 컴포넌트가 `EOnFrame` 안에서 지운 경우에도 그 엔티티를 가리키던 지역 변수와 `ref` 없는 멤버·정적 변수가 그 자리에서 null이 되었습니다. 엔티티가 자기 자신을 지우는 경우(위 `SCR_LifetimeComponent`)와 멀티플레이의 클라이언트(프록시) 쪽은 따로 확인해야 합니다(14장). 오래 들고 있던 엔티티 참조는 쓰기 전에 null인지 확인하고, 주석을 따라 `IsDeleted()`가 true인지도 함께 확인하세요.

## 위치와 변환

### 원점과 회전

엔티티의 위치를 원점(origin)이라고 부릅니다. 자주 쓰는 `IEntity` 메서드는 다음과 같습니다.

| 메서드 | 하는 일 |
|---|---|
| `vector GetOrigin()` / `void SetOrigin(vector orig)` | 위치 읽기·쓰기 |
| `vector GetYawPitchRoll()` / `void SetYawPitchRoll(vector angles)` | 방향을 (요, 피치, 롤) 각도로 읽기·쓰기 |
| `vector GetAngles()` / `void SetAngles(vector angles)` | X, Y, Z축 회전으로 읽기·쓰기 |
| `void GetTransform(out vector mat[])` / `bool SetTransform(vector mat[4])` | 월드 변환 행렬 읽기·쓰기 |
| `vector CoordToParent(vector coord)` / `vector CoordToLocal(vector coord)` | 위치를 로컬 공간과 월드 공간 사이에서 변환 |
| `vector VectorToParent(vector vec)` / `vector VectorToLocal(vector vec)` | 방향 벡터를 같은 방식으로 변환 |

### 변환 행렬

변환 행렬은 `vector` 네 개짜리 정적 배열(`vector mat[4]`)입니다. `mat[3]`이 위치이고, `mat[0]`부터 `mat[2]`까지는 엔티티의 방향을 나타내는 세 축입니다. 공식 코드는 `mat[0]`을 오른쪽 축으로, `mat[2]`(또는 `GetTransformAxis(2)`)를 앞쪽 축으로 쓰며, `mat[1]`이 위쪽 축입니다.

```enforce
vector mat[4];
owner.GetTransform(mat);

// 로컬 좌표 (0 0 2), 즉 앞으로 2m인 위치를 월드 좌표로 구하는 방법(옮기기 전에 계산한다)
vector front = owner.CoordToParent("0 0 2");

vector forward = mat[2];				// 엔티티가 바라보는 방향
mat[3] = mat[3] + forward * 2;			// 앞으로 2m. front와 같은 위치
owner.SetTransform(mat);
```

`CoordToParent`는 엔티티의 지금 변환을 기준으로 계산합니다. 그래서 `SetTransform`으로 옮긴 뒤에 부르면 옮긴 위치에서 다시 2m 앞, 즉 처음 위치에서 4m 앞이 나옵니다. 이름에 Parent가 들어 있지만, 1.8.0.13에서 Hierarchy로 다른 엔티티에 붙인 자식 엔티티로 시험해 보면 부모가 요 90도로 돌아 있어도 `CoordToParent`는 월드 좌표를, `VectorToParent`는 월드 방향을 돌려주었습니다. 부모 기준 값이 필요하면 `GetLocalTransform`, `SetLocalTransform`으로 부모 기준 행렬을 다룹니다.

### 부모와 자식

- `GetParent()`는 부모를, `GetRootParent()`는 맨 위 조상을 돌려줍니다. 부모가 없으면 `GetRootParent()`는 자기 자신입니다.
- `GetChildren()`은 **첫 번째** 자식 하나만 돌려줍니다. 나머지 자식은 `GetSibling()`으로 이어서 찾습니다.
- `AddChild(notnull IEntity child, TNodeId pivot, EAddChildFlags flags = EAddChildFlags.AUTO_TRANSFORM)`로 자식을 붙이고, `RemoveChild(notnull IEntity child, bool keepTransform = false)`로 뗍니다. `pivot`에 -1을 주면 부모의 중심에 붙습니다. 1.8.0.13에서 요 90도로 돌린 부모에 붙여 보면, 기본값 `AUTO_TRANSFORM`으로 붙인 자식은 붙기 전의 월드 위치를 부모 기준 로컬 위치로 써서 부모의 변환을 그 위치에 적용한 자리로 옮겨 갔고, `RECALC_LOCAL_TRANSFORM`이나 `NONE`을 넘긴 자식은 제자리에 남았습니다.

자식 목록을 도는 관용구는 공식 `SCR_EntityHelper.GetChildrenCount()`에도 그대로 나옵니다.

```enforce
int TAG_CountChildren(IEntity parent)
{
	int count;
	IEntity child = parent.GetChildren();
	while (child)
	{
		count++;
		child = child.GetSibling();
	}

	return count;
}
```

새로 만드는 엔티티를 처음부터 자식으로 두려면 `EntitySpawnParams.Parent`에 부모를 지정합니다. 엔진 문서는 먼저 만들고 나중에 붙이는 방식이 리플리케이션에서 문제를 일으킬 수 있다고 경고합니다. 이유는 14장에서 설명합니다.

## 스크립트 엔티티 만들기

컴포넌트로 충분하지 않을 때는 `GenericEntity`를 상속해 새 엔티티 종류를 만듭니다. 구조는 컴포넌트와 같아서, 짝 클래스(`...EntityClass`, 부모는 `GenericEntityClass`)와 `[EntityEditorProps(...)]`가 필요합니다. 위키의 Create an Entity 문서에 따르면 `category`는 World Editor의 **Create** 탭에서 이 엔티티가 들어갈 분류이고, 파일은 역시 `Scripts/Game` 아래에 있어야 목록에 나타납니다.

```enforce title="Scripts/Game/TAG_TickerEntity.c"
[EntityEditorProps(category: "TAG/Tutorial", description: "일정 간격으로 위치를 로그에 남깁니다")]
class TAG_TickerEntityClass : GenericEntityClass
{
}

class TAG_TickerEntity : GenericEntity
{
	[Attribute(defvalue: "5", uiwidget: UIWidgets.Slider, desc: "간격(초)", params: "1 60 1")]
	protected float m_fInterval;

	protected float m_fElapsed;

	override void EOnFrame(IEntity owner, float timeSlice)
	{
		m_fElapsed += timeSlice;
		if (m_fElapsed < m_fInterval)
			return;

		m_fElapsed = 0;
		Print("TAG_TickerEntity 위치: " + owner.GetOrigin());
	}

	void TAG_TickerEntity(IEntitySource src, IEntity parent)
	{
		SetEventMask(EntityEvent.FRAME);
	}
}
```

컴포넌트와 다른 점이 두 가지 있습니다. 엔티티의 생성자는 `(IEntitySource src, IEntity parent)`를 받습니다. 그리고 엔티티의 `SetEventMask`는 소유자 인수 없이 `SetEventMask(EntityEvent e)` 하나만 받으며, 공식 엔티티들은 생성자에서 호출합니다. 컴포넌트의 `SetEventMask(owner, mask)`와 헷갈리지 마세요. `EntityEditorProps`에는 `style`(World Editor에서 그릴 모양, `"box"`, `"sphere"` 등), `sizeMin`, `sizeMax` 같은 시각화 설정이 더 있습니다.

## 정리

<Summary>

- 엔티티(`IEntity`, 스크립트에서는 `GenericEntity`)가 월드의 기본 단위이고 기능은 컴포넌트(`ScriptComponent`)가 맡습니다. 프리팹(`.et`)은 그 구성과 값을 저장한 틀이며 상속할 수 있습니다.
- 컴포넌트와 엔티티에는 정확히 "클래스 이름 + `Class`"인 짝 클래스가 필요하고(없으면 컴파일 오류), 파일은 `Scripts/Game` 아래에 둡니다.
- 컴포넌트는 생성자, `OnPostInit`, `EOnInit` 순서로 초기화되며 이 단계들은 World Editor 편집 중에도 불립니다. 정리 작업은 소멸자가 아니라 `OnDelete`에서 합니다.
- `EOn...` 이벤트는 마스크를 켜야 불립니다. 컴포넌트는 `OnPostInit`에서 `SetEventMask(owner, mask)`, 엔티티는 생성자에서 `SetEventMask(mask)`를 부르고, 필요 없으면 `ClearEventMask`로 끕니다.
- `[Attribute]`의 `defvalue`는 언제나 문자열입니다. 짝 클래스에 둔 어트리뷰트는 같은 프리팹의 인스턴스가 공유하는 프리팹 데이터가 됩니다(World Editor에서 값을 바꾼 인스턴스는 따로 가짐).
- 다른 컴포넌트는 `FindComponent()`로 찾아 `Cast()`하고, `OnPostInit`에서 한 번 찾아 저장해 둡니다.
- 엔티티는 `Resource.Load`, `EntitySpawnParams`, `GetGame().SpawnEntityPrefab`으로 만들고 `SCR_EntityHelper.DeleteEntityAndChildren`으로 지웁니다. 프리팹 생성은 기본적으로 서버에서만 허용됩니다.
- 변환 행렬 `mat[4]`의 `mat[3]`은 위치, `mat[0]`~`mat[2]`는 오른쪽·위·앞 축입니다.

</Summary>
