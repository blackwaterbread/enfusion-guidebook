|---|---|
| `TAG_Radio m_Radio;` | 약한 참조. 멤버 변수는 `ref`가 없으면 약합니다. |
| `ref TAG_Radio m_MainRadio;` | 강한 참조. |

| `ref array<ref TAG_Radio> m_aOwnedRadios;` | 배열 자체와 원소 모두 강한 참조. |
| `static TAG_Radio s_LastRadio;` | 약한 참조. 정적 변수도 `ref`가 없으면 약합니다. |
| 매개변수 `candidate` | 엔진 문서는 강한 참조라고 하지만, 1.8.0.13에서 실행해 보면 객체를 붙잡지 않습니다. 메서드 안에서 다른 강한 참조가 모두 사라지면 객체가 바로 해제되고 `candidate`는 `null`이 됩니다. |
| 지역 변수 `chosen` | 강한 참조. 메서드가 끝나면 놓아줍니다. |
| 반환값 | 강한 참조. 호출한 쪽이 받을 때까지 객체를 붙잡습니다. |

엔진 문서의 규칙대로 기본은 약한 참조이고, `ref`를 붙인 변수와 지역 변수·반환값만 객체를 붙잡습니다. 엔진 문서는 매개변수도 강한 참조라고 하지만 실행 결과는 위 표와 같습니다.

<Answer id="7-2">

문제는 두 군데입니다.

1. `m_aItems`는 `ref`가 없는 멤버 변수라서 약한 참조입니다. `new`로 만든 배열을 넣어도 붙잡는 강한 참조가 없으므로, 컴파일러가 생성자의 대입을 `Variable 'm_aItems' is not strong ref (missing 'ref'?)` 오류로 막습니다.
2. 배열을 살려도 원소 타입이 `array<TAG_Item>`이라 원소가 약한 참조입니다. `new TAG_Item(name)`으로 만든 아이템은 배열에 들어가자마자 해제됩니다. 이쪽은 컴파일러가 잡지 못하는 실행 중 문제입니다.

고친 코드는 다음과 같습니다.

```enforce
class TAG_Item
{
	protected string m_sName;

	void TAG_Item(string name)
	{
		m_sName = name;
	}
}

class TAG_Inventory
{
	protected ref array<ref TAG_Item> m_aItems = {};

	//------------------------------------------------------------------------------------------------
	void AddItem(string name)
	{
		m_aItems.Insert(new TAG_Item(name));
	}

	//------------------------------------------------------------------------------------------------
	int GetItemCount()
	{
		return m_aItems.Count();
	}
}
```

인벤토리가 배열을 소유하고, 배열이 아이템을 소유하므로 `ref`를 두 번 씁니다. 공식 스크립트처럼 선언과 함께 `= {}`로 배열을 만들면 생성자를 따로 두지 않아도 됩니다.

</Answer>

<Answer id="7-4">

차량은 운전자를, 운전자는 차량을 `ref`로 붙잡고 있어 순환 참조가 생깁니다. 바깥의 참조가 모두 사라져도 두 객체가 서로를 붙잡아 참조 수가 0이 되지 않으므로 해제되지 않습니다.

차량이 운전자를 소유한다고 보면, 차량에서 운전자로 가는 참조는 강하게, 운전자에서 차량으로 거슬러 가는 참조는 약하게 둡니다.

```enforce title="Scripts/Game/TAG_Car.c"
class TAG_Car
{
	protected string m_sName;
	protected ref TAG_Driver m_Driver;

	//------------------------------------------------------------------------------------------------
	void TAG_Car(string name)
	{
		m_sName = name;
	}

	//------------------------------------------------------------------------------------------------
	string GetName()
	{
		return m_sName;
	}

	//------------------------------------------------------------------------------------------------
	TAG_Driver CreateDriver()
	{
		m_Driver = new TAG_Driver(this);
		return m_Driver;
	}
}

class TAG_Driver
{
	protected TAG_Car m_Car; // 약한 참조: 소유자를 거꾸로 가리킴

	//------------------------------------------------------------------------------------------------
	void TAG_Driver(TAG_Car car)
	{
		m_Car = car;
	}

	//------------------------------------------------------------------------------------------------
	string GetVehicleName()
	{
		if (!m_Car)
			return "on foot";

		return m_Car.GetName();
	}
}

class TAG_CarDemo
{
	static void Run()
	{
		TAG_Car car = new TAG_Car("Truck");
		TAG_Driver driver = car.CreateDriver();
		Print(driver.GetVehicleName());

		car = null; // 차량을 붙잡던 마지막 강한 참조
		Print(driver.GetVehicleName());
	}
}
```

실행 결과는 다음과 같습니다.

```text
Truck
on foot
```

`car = null`로 차량의 마지막 강한 참조가 사라지면 차량이 해제됩니다. 운전자는 지역 변수 `driver`가 아직 붙잡고 있어 살아남고, 운전자의 `m_Car`는 약한 참조이므로 `null`이 됩니다. `GetVehicleName()`이 `m_Car`를 확인하므로 이 상황에서도 안전합니다.

</Answer>

<Answer id="7-5">

```enforce title="Scripts/Game/TAG_ItemRegistry.c"
class TAG_Item
{
	protected string m_sName;

	//------------------------------------------------------------------------------------------------
	void TAG_Item(string name)
	{
		m_sName = name;
	}

	//------------------------------------------------------------------------------------------------
	void ~TAG_Item()
	{
		PrintFormat("item destroyed: %1", m_sName);
	}
}

class TAG_ItemRegistry
{
	protected ref map<string, ref TAG_Item> m_mItems = new map<string, ref TAG_Item>();

	//------------------------------------------------------------------------------------------------
	TAG_Item Register(string name)
	{
		TAG_Item item = new TAG_Item(name);
		m_mItems.Set(name, item);
		return item;
	}

	//------------------------------------------------------------------------------------------------
	void Unregister(string name)
	{
		m_mItems.Remove(name);
	}
}

class TAG_ItemLabel
{
	TAG_Item m_Item; // 약한 참조: 아이템을 가리키기만 함
}

class TAG_RegistryDemo
{
	static void Run()
	{
		TAG_ItemRegistry registry = new TAG_ItemRegistry();
		TAG_ItemLabel label = new TAG_ItemLabel();

		label.m_Item = registry.Register("Medkit"); // 지역 변수에 받지 않음
		Print("registered");

		registry.Unregister("Medkit");
		if (!label.m_Item)
			Print("label lost its item");
	}
}
```

실행 결과는 다음과 같습니다.

```text
registered
item destroyed: Medkit
label lost its item
```

- 레지스트리의 맵은 `map<string, ref TAG_Item>`이므로 값으로 들어간 아이템을 강하게 붙잡습니다. 맵 자체도 `ref` 멤버로 둡니다.
- `Register`의 반환값은 대입문이 끝나면 사라지고, 라벨의 `m_Item`은 약한 참조입니다. 따라서 아이템을 붙잡는 강한 참조는 맵 하나뿐입니다.
- `Unregister`가 맵에서 항목을 지우면 마지막 강한 참조가 사라져 아이템이 해제되고, 라벨의 `m_Item`은 `null`이 됩니다.
- 만약 `TAG_Item medkit = registry.Register("Medkit");`처럼 반환값을 지역 변수에 받았다면, 그 지역 변수가 강한 참조로 남아 있어 `Unregister` 뒤에도 아이템이 해제되지 않습니다. 이 경우에는 `medkit = null;`을 한 뒤에야 해제됩니다.

</Answer>
