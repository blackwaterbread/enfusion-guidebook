|---|---|---|
| `a` | `3` | `int`끼리 나눈 식을 `int` 변수에 담으므로 소수 부분을 버린 정수입니다. |

| `d` | `2` | 17을 5로 나눈 나머지입니다. |

| `f` | `2.25` | 형변환 `(float)`가 나눗셈보다 먼저 적용되어 9.0을 4로 나눕니다. |
| `g` | `3` | `Math.Round(2.6)`은 `float` 3.0을 돌려주고, 그 값이 `int`에 들어갑니다. |
| `h` | `16` | 1을 왼쪽으로 4비트 밀면 2의 4제곱입니다. |

`a`와 `b`의 차이가 이 문제의 핵심입니다. 같은 `7 / 2`라도 `int`에 담으면 3, `float`에 담으면 3.5입니다. 받는 곳에 따라 결과가 달라지므로, 실수 결과가 필요하면 `f`처럼 `(float)`로 의도를 드러내는 편이 안전합니다.

```enforce title="Scripts/Game/TAG_AmmoParser.c"
class TAG_AmmoParser
{
	//------------------------------------------------------------------------------------------------
	//! 문자열 앞쪽의 숫자를 읽어 돌려줍니다. 숫자를 하나도 읽지 못하면 -1을 돌려줍니다.
	static int ParseAmmo(string text)
	{
		int readChars;
		int ammo = text.ToInt(parsed: readChars);
		if (readChars == 0)
			return -1;

		return ammo;
	}

	//------------------------------------------------------------------------------------------------
	static void Test()
	{
		Print("'30' -> " + ParseAmmo("30"));
		Print("' 12 rounds' -> " + ParseAmmo(" 12 rounds"));
		Print("'none' -> " + ParseAmmo("none"));
		Print("'0' -> " + ParseAmmo("0"));
	}
}
```

Remote Console에서 `TAG_AmmoParser.Test();`를 실행한 결과는 다음과 같습니다.

```text
'30' -> 30
' 12 rounds' -> 12
'none' -> -1
'0' -> 0
```

- `ToInt`는 앞쪽 공백을 건너뛰고 숫자가 아닌 글자에서 멈추므로 `" 12 rounds"`는 12가 됩니다.
- `"none"`과 `"0"`은 `ToInt()`의 반환값만 보면 둘 다 0입니다. `parsed`로 받은 읽은 글자 수가 0인지 보아야 둘을 구별할 수 있습니다. 공식 문서에 따르면 `"0"`은 읽은 글자 수가 1이고 `"abc"`는 0입니다.
- 이 메서드는 실패를 -1로 알리므로 음수 탄약 수는 다룰 수 없습니다. 실패 여부와 값을 따로 돌려주고 싶다면 4장의 `out` 매개변수를 써서 `bool TryParseAmmo(string text, out int ammo)` 형태로 만들 수 있습니다.

</Answer>

```enforce title="Scripts/Game/TAG_EPermission.c"
//! 서버 관리 권한 플래그
enum TAG_EPermission
{
	KICK          = 1 << 0,    // 1
	BAN           = 1 << 1,    // 2
	SPAWN_VEHICLE = 1 << 2,    // 4
	EDIT_WORLD    = 1 << 3,    // 8
}
```

```enforce title="Scripts/Game/TAG_PermissionDemo.c"
class TAG_PermissionDemo
{
	//------------------------------------------------------------------------------------------------
	static void Run()
	{
		// 1. KICK과 SPAWN_VEHICLE을 합친 권한
		TAG_EPermission permissions = TAG_EPermission.KICK | TAG_EPermission.SPAWN_VEHICLE;

		// 2. BAN 권한 검사
		if (permissions & TAG_EPermission.BAN)
			Print("Can ban");
		else
			Print("Cannot ban");

		// 3. KICK 권한 빼기
		permissions &= ~TAG_EPermission.KICK;

		// 4. 남은 권한 이름 출력
		Print("Remaining: " + SCR_Enum.FlagsToString(TAG_EPermission, permissions));
	}
}
```

실행 결과는 다음과 같습니다.

```text
Cannot ban
Remaining: SPAWN_VEHICLE
```

- 값을 1, 2, 4, 8로 정해야 각 권한이 서로 다른 비트를 차지하므로 `|`로 합쳐도 섞이지 않습니다.
- `permissions & TAG_EPermission.BAN`은 해당 비트가 켜져 있으면 0이 아닌 값이 되어 조건식에서 참으로 판정됩니다. 공식 코드도 `if (threatFlags & SCR_EAIThreatSectorFlags.CAUSED_DAMAGE)`처럼 씁니다.
- `&= ~KICK`은 KICK 비트만 0으로 만들고 나머지 비트는 그대로 둡니다.
- `SCR_Enum.FlagsToString`은 켜진 비트마다 `typename.EnumToString`으로 이름을 얻어 `", "`로 잇습니다. 값이 0이면 `"N/A"`를 돌려줍니다.

<Answer id="2-5">

문제가 되는 곳은 네 군데입니다.

1. **나눗셈**: `float ratio`에 바로 담으므로 실행하면 실수로 계산되지만(3과 2면 1.5), 같은 식을 `int`에 담거나 `Print`에 넘기면 버려지므로 `(float)`로 의도를 드러내는 편이 안전합니다. 또 `deaths`가 0이면 0으로 나누게 됩니다.
2. **삼항 연산자**: Enforce Script는 `? :`를 지원하지 않아 컴파일 오류가 납니다.
3. **연산자 우선순위**: `==`가 `&`보다 먼저 계산되어 `m_iFlags & (AIR == AIR)`로 묶입니다.
4. **문자열 연결 순서**: `kills + " kills..."`는 왼쪽이 `int`라서 오류입니다. `+`로 문자열을 이을 때는 왼쪽이 문자열이어야 합니다.

고친 코드는 다음과 같습니다.

```enforce title="Scripts/Game/TAG_StatsReporter.c"
class TAG_StatsReporter
{
	protected int m_iFlags;

	//------------------------------------------------------------------------------------------------
	void Report(int kills, int deaths)
	{
		// 0으로 나누지 않도록 먼저 검사하고, 나누기 전에 float로 바꿉니다.
		float ratio = kills;
		if (deaths > 0)
			ratio = (float)kills / deaths;

		// 삼항 연산자 대신 if
		string status = "bad";
		if (ratio > 1)
			status = "good";

		// 비트 검사는 괄호로 묶습니다. SCR_Enum.HasFlag(m_iFlags, TAG_EUnitFlags.AIR)도 같은 뜻입니다.
		bool isAir = (m_iFlags & TAG_EUnitFlags.AIR) == TAG_EUnitFlags.AIR;

		// 숫자로 시작하는 문장은 PrintFormat으로 만듭니다.
		PrintFormat("%1 kills, status: %2", kills, status);
		if (isAir)
			Print("Air unit");
	}
}
```

데스가 0일 때 비율을 킬 수로 보는 것은 하나의 선택입니다. 중요한 것은 나누기 전에 0인지 검사하는 습관입니다. 문자열 연결은 `kills.ToString() + " kills"`로 써도 됩니다.

</Answer>
