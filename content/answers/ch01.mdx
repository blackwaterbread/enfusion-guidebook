Remote Console에 다음 세 줄을 입력하고 **Run**을 누릅니다.

```enforce
Print("My first Enforce Script");
Print("10 * 4 = " + (10 * 4));
PrintFormat("Progress: %1%%", 80);
```

- 두 번째 줄은 문자열 뒤에 정수를 `+`로 이어 붙였습니다. 왼쪽이 문자열이면 오른쪽 값은 문자열로 바뀌어 연결됩니다. `*`가 `+`보다 먼저 계산되므로 괄호가 없어도 결과는 같지만, 계산 부분을 괄호로 묶으면 의도가 분명해집니다.
- 같은 줄을 `PrintFormat("%1 * %2 = %3", 10, 4, 10 * 4);`로 써도 됩니다.
- 세 번째 줄의 `%1`은 첫 번째 인수 80으로 바뀝니다. `PrintFormat`에서 `%`는 특수 문자이므로 퍼센트 기호를 출력하려면 `%%`로 씁니다.

</Answer>

<Answer id="1-3">

```enforce title="Scripts/Game/TAG_Greeter.c"
//! 1장 연습문제: 정적 메서드를 콘솔에서 호출합니다.
class TAG_Greeter
{
	//------------------------------------------------------------------------------------------------
	static void Greet()
	{
		Print("Hello from TAG_Greeter!");
	}

	//------------------------------------------------------------------------------------------------
	static void PrintGoals()
	{
		Print("Goal 1: Open the Script Editor");
		Print("Goal 2: Compile a script file");
		Print("Goal 3: Call a method from the console");
	}
}
```

파일을 저장하고 **Build > Validate and Reload Scripts**로 컴파일한 뒤, Remote Console에서 다음 두 줄을 실행합니다.

```enforce
TAG_Greeter.Greet();
TAG_Greeter.PrintGoals();
```

실행 결과는 다음과 같습니다.

```text
Hello from TAG_Greeter!
Goal 1: Open the Script Editor
Goal 2: Compile a script file
Goal 3: Call a method from the console
```

- 두 메서드에 `static`을 붙였기 때문에 객체를 만들지 않고 `클래스이름.메서드이름()`으로 부를 수 있습니다. 정적 메서드는 5장에서 자세히 다룹니다.
- 파일 이름(`TAG_Greeter.c`)과 클래스 이름(`TAG_Greeter`)을 같게 맞췄습니다.
- 콘솔의 실행 환경은 본문에서 안내한 대로 **Game**으로 둡니다.

</Answer>

<Answer id="1-5">

엔진 문서(Language Server Protocol, Features, Visual Studio Code configuration, CLI)에 근거한 점검 순서입니다.

1. **Workbench가 실행 중인가.** LSP 서버는 Workbench 안에서 동작하므로, 꺼져 있으면 접속할 서버가 없습니다.
2. **Workbench Options에서 LSP를 켰는가.** 켜지 않으면 서버가 TCP 연결을 받지 않습니다. 명령줄에서 `-lsp`로 실행했다면 이미 켜져 있습니다.
3. **포트 번호가 같은가.** VS Code 확장(`lsp-enforcescript-extension`) 설정의 포트와 Workbench 옵션의 포트가 같아야 합니다. 기본값은 5776이고, `-lspPort`로 실행했다면 그 값을 씁니다. 문서가 첫 번째로 꼽는 문제 원인입니다.
4. **편집기의 언어 모드가 `Enforce`인가.** 상태 표시줄의 언어가 다르면 확장이 그 파일을 Enforce Script로 다루지 않습니다.
5. **파일이 디스크에 있고 프로젝트의 올바른 스크립트 폴더 안에 있는가.** LSP는 실제 파일에만 연결되며, 스크립트가 올바른 위치에 있어야 합니다.
6. **클라이언트를 다시 시작했는가.** 설정을 바꾼 뒤에는 <Kbd>Ctrl</Kbd>+<Kbd>Shift</Kbd>+<Kbd>P</Kbd>로 **LSP Client restart**를 실행하거나 <Kbd>Ctrl</Kbd>+<Kbd>Alt</Kbd>+<Kbd>D</Kbd>를 눌러 다시 연결합니다.
7. **모든 `.c` 파일을 저장했는가.** 저장하기 전에는 문법·어휘 오류만 오고, 모두 저장해야 완전한 진단 정보가 옵니다.

마지막으로, 이 기능은 아직 실험 단계라는 점을 동료와 공유하세요. 문서는 서버가 편집 중인 파일에 직접 쓰기 작업을 하므로 편집기에서 예상하지 못한 일이 생길 수 있다고 경고합니다.

</Answer>
