Enforce Script 열은 Arma Reforger 1.8.0.13의 엔진 문서와 공식 스크립트로 확인한 내용이고, 다른 언어 열은 Python 3, 최신 JavaScript, C#의 일반적인 문법을 적었습니다. 표는 짧게 줄였으므로 자세한 규칙은 마지막 열의 장을 보세요.

## 사고방식이 가장 크게 다른 곳

문법 차이는 금방 익숙해지지만, 아래 여섯 가지는 머릿속 그림을 바꿔야 합니다. 다른 언어의 습관대로 쓰면 버그로 이어지기 쉬운 차이이기도 합니다.

### 진입점이 없다

Python과 JavaScript는 파일을 위에서부터 실행하고, C#은 `Main` 메서드에서 시작합니다. Enforce Script에는 내가 정하는 진입점이 없습니다. 엔진이 엔티티와 컴포넌트의 이벤트(10장), 게임 모드의 콜백(11장)을 부르거나, `modded` 클래스로 바꿔 끼운 메서드(12장)가 불릴 때 내 코드가 실행됩니다. 파일 맨 위에 실행문을 쓰면 컴파일 오류가 납니다(1장).

<Compare title="코드가 실행되는 자리">

```python
# 파일을 실행하면 맨 위부터 바로 실행됨
print("Mod loaded")
```

```enforce
// 클래스 안의 메서드만 실행됨. 누가 부를지는 엔진 쪽 구조가 정함
class TAG_Startup
{
	static void OnLoaded()
	{
		Print("Mod loaded");
	}
}
```

</Compare>

### import 없이 모듈 전체가 함께 컴파일된다

같은 스크립트 모듈의 `.c` 파일은 모두 함께 컴파일되고, 다른 파일의 클래스를 이름만으로 씁니다(1장). 이름 공간이 하나뿐이므로 모든 클래스와 전역 함수에 태그(`TAG_`)를 붙여 다른 모드와 이름이 겹치지 않게 합니다.

### 멤버 변수의 참조는 기본이 약하다

Python, JavaScript, C#에서는 객체를 어딘가에 담아 두기만 하면 살아 있습니다. Enforce Script의 `Managed` 객체는 강한 참조가 하나도 남지 않으면 바로 지워집니다. 엔진 문서에 따르면 지역 변수, 함수 인수, 반환값은 기본적으로 강한 참조이지만(실행해 보면 함수 인수는 객체를 붙잡지 않습니다, 7장), 멤버 변수는 기본적으로 약한 참조이므로, 객체를 멤버에 담아 두려면 `ref`를 붙여야 합니다. 서로를 `ref`로 가리키는 순환 참조는 저절로 정리되지 않습니다(7장).

<Compare title="객체를 멤버에 담아 두기">

```python
class Squad:
    def __init__(self):
        self.members = []    # Squad가 살아 있는 동안 리스트도 살아 있음
```

```enforce
class TAG_Squad
{
	protected ref array<string> m_aMembers = {};    // ref가 있어야 강한 참조
}
```

</Compare>

### 예외 처리 구문이 없다

`try`/`catch`가 없습니다. `null` 객체에 접근하는 것 같은 실행 중 오류는 가상 머신 예외(VM Exception)로 나타나고, 코드에서 잡을 수 없습니다. 그래서 공식 코드는 조기 `return`으로 `null`을 걸러 내고, 실패할 수 있는 함수는 `bool`을 돌려주고 결과는 `out` 매개변수로 넘깁니다(3장, 4장, 15장).

### 시간을 기다리는 방법이 다르다

`async`/`await`나 `setTimeout`이 없습니다. 일정 시간 뒤에 무언가를 하려면 콜 큐의 `GetGame().GetCallqueue().CallLater()`에 메서드를 맡깁니다. `thread` 키워드는 Workbench 플러그인용입니다(4장, 11장).

### 남의 코드를 고치는 방법이 다르다

Python의 몽키 패칭이나 JavaScript의 프로토타입 수정 대신, `modded class`로 기존 클래스를 같은 이름의 내 클래스로 바꿔 끼우고 `super`로 원래 동작을 부릅니다(12장).

## 비교표를 쓸 때 주의할 점

- 비슷해 보이는 문법도 의미가 다를 수 있습니다. 예를 들어 `if (items)`는 Python에서는 비어 있지 않은지 묻지만, Enforce Script에서는 배열 객체가 있는지(`null`이 아닌지)만 묻습니다.
- C#과 가장 비슷하지만 C#의 많은 기능(삼항 연산자, 람다, 예외, 인터페이스, `do`/`while`)이 없습니다. "C#이라면 이렇게 쓸 텐데"라는 생각이 들면 이 부록과 공식 스크립트에서 같은 일을 하는 코드를 먼저 찾아보세요.
- Python과 JavaScript의 맵은 넣은 순서를 지키지만, Enforce Script의 `map`과 `set`은 순서를 보장하지 않습니다. 순서가 중요하면 배열을 함께 씁니다(8장).
