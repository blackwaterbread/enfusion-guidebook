<Objectives>

- Remote Console에서 실행 환경을 고르고 코드를 실행해 Output에서 결과를 볼 수 있다.
- Output, Log Console, 로그 파일 가운데 무엇을 어디서 찾을지 고를 수 있다.
- VME 대화상자와 알림을 알아보고, 로그에서 `Reason:`과 `Stack trace:`를 찾을 수 있다.
- **Script Authorization Required** 대화상자가 묻는 내용을 읽을 수 있다.
- 디버거의 **Debug** 메뉴와 Breakpoints, Watch, Callstack 창을 화면에서 찾을 수 있다.

</Objectives>

4장에서 스크립트 파일을 만들고 컴파일했습니다. 이 장에서는 컴파일한 코드를 **Remote Console**에서 실행하고, 출력과 오류가 어디에 남는지, 실행 중 오류(VME)와 디버거가 화면에 어떻게 나타나는지 봅니다.

`Print`와 `PrintFormat`, 로그 수준, 디버거를 쓰는 방법과 실습은 Script 책 15장에 있습니다. 이 장은 그 내용을 따라 할 때 필요한 창, 메뉴, 대화상자만 다룹니다.

## Remote Console

**Remote Console**은 코드를 입력해 바로 실행하는 창입니다. 4장의 배치에서는 Script Editor 아래 오른쪽에 **Text Search** 탭과 함께 있습니다. 보이지 않으면 **Window** 메뉴에서 **Remote Console**을 찾습니다(4장).

창 위쪽 왼쪽에는 실행 환경 목록과 **Run** 버튼이, 오른쪽에는 실행 기록 목록이 있고, 그 아래가 줄 번호가 붙은 입력 칸입니다(<FigRef id="ch05-remote-console" />). **Run**을 누르면 입력 칸의 코드가 실행되고 결과가 **Output** 창에 나옵니다. 실행이 끝나면 Output에 `ScriptDebugger: remote script executed successfully.` 줄이 더해집니다. 코드에서 VME가 나도 이 줄은 찍히므로, 이 줄은 오류가 없었다는 뜻이 아닙니다.

<Figure src="ch05/remote-console.png" alt="Remote Console과 Output 창" id="ch05-remote-console">Remote Console과 Output 창</Figure>

<TryIt title="콘솔에서 한 줄 실행하기">

1. Script Editor를 엽니다(4장).
2. 아래 오른쪽의 **Remote Console** 탭과 아래 가운데의 **Output** 탭을 눌러 두 창을 앞에 둡니다.
3. 실행 환경 목록이 `Game`인지 확인합니다.
4. 입력 칸에 `Print("Hello World");`를 입력하고 **Run**을 누릅니다.
5. **Output**에 `Hello World` 줄과 `ScriptDebugger: remote script executed successfully.` 줄이 나옵니다. 두 줄 앞에는 `SCRIPT`가 붙습니다.
6. 4장에서 `TAG_HelloWorld.c`를 만들어 **Validate and Reload Scripts**로 컴파일했다면 입력 칸을 `TAG_HelloWorld.SayHello();`로 바꿔 실행해 봅니다. **Output**에 Script 책 1장의 실행 결과 두 줄이 나옵니다.

</TryIt>

### 실행 환경

실행 환경 목록에는 `Engine`, `GameLib`, `Game`, `Entities`, `WorkbenchGame`, `Workbench`가 있습니다(<FigRef id="ch05-console-env" />). 그림에서는 `Game`이 골라져 있습니다. 이 이름들은 4장에서 본 **Validate Scripts** 결과의 모듈 이름과 같습니다. Script 책의 예제는 `Game`에서 실행합니다. 프로젝트의 `Scripts/Game`에 둔 클래스(예: `TAG_HelloWorld`)는 `Game`과 `WorkbenchGame`에서 부를 수 있습니다. `Engine`, `GameLib`, `Entities`, `Workbench`에서 부르면 `Can't find variable 'TAG_HelloWorld'` 오류가 나고, `executed successfully` 줄도 찍히지 않습니다.

<Figure src="ch05/console-env.png" alt="Remote Console의 실행 환경 목록" id="ch05-console-env">Remote Console의 실행 환경 목록</Figure>

### 언제 실행할 수 있나

**Run**은 월드를 열지 않고 Play도 하지 않은 상태에서도, World Editor에서 Play 중일 때도 동작합니다. 위키(Script Editor)는 콘솔을 쓰려면 플레이 모드여야 한다고 적고, 위키(Scripting Example)는 World Editor에서 게임이 돌고 있지 않으면 **Run**을 누른 다음 컴파일하라고 안내합니다. 실제로는 둘 다 필요하지 않습니다. Workbench가 시작할 때 스크립트를 컴파일해 두기 때문입니다(4장).

Workbench를 띄운 뒤에 만들거나 고친 스크립트는 **Build > Validate and Reload Scripts**로 다시 컴파일한 다음 실행합니다(4장).

### 입력을 돕는 기능

- 실행 기록: 오른쪽 목록에 **Run**한 줄이 쌓입니다.
- 자동 완성: 이름을 입력하는 중에 자동 완성 목록이 뜨고, <Kbd>Tab</Kbd>으로 고른 이름을 넣습니다. 대소문자를 가리지 않고 이름 중간 글자로도 찾습니다. 예를 들어 `hellow`를 입력하면 `TAG_HelloWorld`가 목록에 나옵니다.
- 입력 칸의 코드는 Workbench를 다시 띄워도 그대로 남습니다. 새 코드를 넣기 전에 이전 줄을 지웁니다.

**Debug > Console Execute**(<Kbd>F6</Kbd>)는 **Run**과 같이 입력 칸의 코드를 실행합니다. 커서가 편집 영역에 있을 때 <Kbd>F6</Kbd>을 눌러도 같습니다.

### 멈춘 상태의 콘솔

콘솔에서 부른 코드가 `debug;` 문에서 멈춰 있는 동안에는 **Run**이 흐리게 표시됩니다. Play 중 게임 코드가 브레이크포인트에서 멈춘 동안에는 **Run**이 켜져 있고, 입력한 코드는 멈춘 자리의 문맥에서 실행되어 매개변수와 멤버 변수를 쓸 수 있습니다. Script 책 15장도 같은 내용을 소개합니다.

## 출력과 로그가 남는 곳

`Print` 출력, 컴파일 경고, VME 같은 줄은 다음 세 곳에 남습니다.

| 곳 | 위치 | 보이는 것 |
|---|---|---|
| **Output** | Script Editor 아래 가운데 | `Print` 출력, Remote Console 결과, 컴파일 메시지와 경고 |
| **Log Console** | 메인 창 아래, World Editor 아래의 탭 | `Print` 출력과 VME 같은 로그 줄, 엔진의 다른 줄, 오류·경고·정보 개수 |
| 로그 파일 | `C:\Users\<사용자 이름>\Documents\My Games\ArmaReforgerWorkbench\logs` | Workbench를 띄울 때마다 새 폴더에 `console.log`, `script.log`, `error.log` |

### Output

**Output**에 찍히는 로그 줄 앞에는 분류 이름 `SCRIPT`가 붙고, 경고 줄에는 `SCRIPT` 뒤에 `(W)`가 더 붙습니다. 4장에서 본 **Validate Scripts**의 결과 줄(`Compilation`, `Succeeded:`)도 여기에 나오는데, 이 줄들에는 `SCRIPT`가 붙지 않습니다.

`Debug.GetEntityLinkString()`(Script 책 15장)이 만든 엔티티 링크 문자열(`@"ENTITY:…"`)은 Output에서는 링크로 보이지 않고 눌러도 반응이 없습니다. 링크는 다음 절의 Log Console에서 씁니다.

### Log Console

**Log Console**은 메인 창 아래쪽과 World Editor 아래쪽에 있습니다. World Editor에서는 **Resource Browser**, **Prefab Library** 탭 옆의 **Log Console** 탭입니다. 메인 창의 **Window** 메뉴에도 **Log Console** 항목이 있습니다. 메인 창의 창 배치는 2장, World Editor는 6장에서 봅니다.

World Editor의 Log Console에도 메인 창의 것처럼 검색 칸, **Clear Console** 버튼, 오류·경고·정보 아이콘과 개수, 깔때기 버튼과 톱니 버튼이 있습니다(<FigRef id="ch05-log-console" />). 각 부분은 2장에서 보았으니, 여기서는 로그 줄을 읽는 법을 봅니다. 노란 삼각형과 파란 i는 Errors 창(4장)의 경고·힌트 아이콘과 같은 모양입니다.

<Figure src="ch05/log-console.png" alt="World Editor의 Log Console" id="ch05-log-console">World Editor의 Log Console</Figure>

- `SCRIPT` 말고 `RESOURCES`, `WORLD`, `ENTITY`, `GUI`, `DEFAULT`, `PROFILING`, `TERRAIN`, `RENDER` 같은 다른 분류의 줄도 보입니다.
- 경고 줄에는 분류 뒤에 `(W)`가, 오류 줄에는 `(E)`가 붙습니다. 오류 줄은 빨간 글자로 찍힙니다.
- VME 줄은 빨간 글자로 찍히고, 빨간 × 옆 숫자에 더해집니다.
- **Clear Console**은 창의 줄만 지웁니다. 로그 파일의 내용은 그대로 남습니다.
- 검색 칸에 `link`처럼 글자를 넣으면 다른 줄도 그대로 보이고, 맞는 글자만 파랗게 표시됩니다. <Kbd>Enter</Kbd>를 눌러도 표시는 바뀌지 않습니다.
- World Editor의 Log Console은 오류·경고·정보 아이콘이 하나도 눌리지 않은 상태로 시작합니다. 아이콘 하나를 누르면 그 종류의 줄만 남고, 다시 누르면 모든 줄이 보입니다. 메인 창의 Log Console은 세 아이콘이 모두 눌린 상태로 시작하므로, 아이콘을 누르면 그 종류의 줄이 숨습니다(2장). 깔때기 버튼과 톱니 버튼이 여는 메뉴는 메인 창과 같습니다.
- 메인 창의 Log Console에서는 `@"…"`로 파일이나 엔티티를 가리키는 부분이 보라색 밑줄 글자로 보입니다.
- World Editor의 Log Console에서는 엔티티 링크가 보라색 링크로 보입니다. 편집 모드에서 누르면 그 엔티티가 선택되고 카메라가 그쪽으로 옮겨 갑니다. Play 중에 누르면 화면에 변화가 없습니다.

### 로그 파일

Workbench는 띄울 때마다 `…\ArmaReforgerWorkbench\logs` 아래에 시작 날짜와 시각을 이름으로 한 폴더를 만들고 거기에 로그를 씁니다. 폴더 구성은 다음과 같습니다.

```text
C:\Users\<사용자 이름>\Documents\My Games\ArmaReforgerWorkbench\
├─ addons\
├─ logs\
│  └─ logs_<날짜>_<시각>\
│     ├─ console.log
│     ├─ error.log
│     └─ script.log
└─ profile\
```

세 로그 파일은 첫머리에 자기 전체 경로와 시작 시각을 적습니다. 파일마다 담는 줄은 다음과 같습니다.

| 파일 | 담는 줄 |
|---|---|
| `console.log` | 엔진, 리소스, 스크립트 줄이 모두 들어 있어 가장 자세합니다 |
| `script.log` | 스크립트 줄. 컴파일 경고, `Print` 출력, VME |
| `error.log` | 경고와 오류 줄과 그 줄이 속한 단계의 줄. VME는 있고 `Print` 출력은 없습니다 |

Workbench 안에서도 이번 세션의 로그를 열 수 있습니다. 메인 창 Resource Browser 트리의 `logs`가 이번 세션의 로그 폴더이고(3장), 그 안의 `console.log`를 두 번 클릭하면 메인 창의 탭에 글자로 열립니다.

세션 폴더에는 이 밖에 `resourceDatabase.rdb` 파일과 `.backend` 폴더도 있습니다. Workbench는 띄울 때 가장 오래된 세션 폴더부터 지워, 새 세션 폴더 말고 10개를 남깁니다. 남겨 둘 로그는 다른 곳에 복사해 둡니다. 엔진 문서(Command line interface)에 따르면 남겨 두는 로그 개수는 시작 매개변수 `-keepNumOfLogs`로 정하고 기본값은 10입니다.

로그 수준과 로그 폴더를 바꾸는 시작 매개변수(`-logLevel`, `-logsDir` 등)와 게임·서버 실행 파일의 로그는 Script 책 15장에서 다룹니다.

<Note title="OneDrive와 로그 폴더">

문서 폴더가 OneDrive에 있는 PC에서는 **New Project** 창의 **Location** 기본값(1장)과 마찬가지로 Workbench의 `logs`와 `profile` 폴더도 `C:\Users\<사용자 이름>\OneDrive\문서\My Games\ArmaReforgerWorkbench`처럼 OneDrive 안에 있습니다. 로그를 찾을 때는 이 폴더를 봅니다.

</Note>

## VME가 났을 때

스크립트 실행 중에 처리되지 않은 문제가 생기면 VME(Virtual Machine Exception)가 납니다. 흔한 원인과 대처는 Script 책 15장에서 다룹니다. VME가 나면 Workbench는 화면 오른쪽 아래에 알림을 띄우고, 새로 띄운 Workbench 세션에서는 **Virtual machine exception** 대화상자도 함께 띄웁니다. 다음 경우에는 대화상자 없이 알림만 뜨고 실행이 이어집니다.

- 그 세션에서 대화상자의 **Ignore All**을 누른 뒤
- 그 세션에서 Play를 한 번이라도 시작한 뒤(Play 중과 Play를 끝낸 뒤의 편집 모드 모두)
- 시작 매개변수 `-VMErrorMode log_only`나 `-noThrow`로 띄운 세션(이 절 뒤쪽)

Script Editor를 열었는지와는 상관이 없습니다. **Ignore All**이나 Play 때문에 알림만 뜨던 경우에도 Workbench를 새로 띄우면 다시 대화상자가 함께 뜹니다.

`Debug.Error()`(Script 책 15장)도 VME로 보고되어 같은 알림이 뜨고, 로그의 `Reason:` 줄에 넘긴 메시지가 남습니다. 대화상자가 뜨는 세션에서는 제목이 `We have Error() Check stated Line!`인 대화상자가 뜹니다. 내용의 꼴과 버튼은 VME 대화상자와 같습니다.

### 대화상자

대화상자에는 `Virtual Machine Exception` 아래로 `Reason:`(원인, 예: `NULL pointer to instance`), `Class:`, `Function:`, `Stack trace:`와 그 아래 `파일:줄 Function 함수 이름` 줄이 나옵니다(<FigRef id="ch05-vme-dialog" />). `Stack trace:` 아래에는 첫 줄만 보이므로, 나머지 줄은 <strong>Show Details...</strong>나 로그에서 봅니다. 대화상자가 떠 있는 동안 그 스크립트의 실행은 멈춥니다. 아래쪽 버튼은 넷입니다.

<Figure src="ch05/vme-dialog.png" alt="Virtual machine exception 대화상자" id="ch05-vme-dialog">Virtual machine exception 대화상자</Figure>

| 버튼 | 하는 일 |
|---|---|
| **Debug** | Script Editor가 열리고, VME가 난 파일의 그 줄에서 실행이 멈춥니다. 줄 번호 옆에 노란 화살표가 붙고 Callstack 창에 호출 순서가 나옵니다. **Continue**(<Kbd>F5</Kbd>)로 이어 가면 같은 VME가 로그에 다시 남고 대화상자가 다시 뜹니다 |
| **Ignore** | 그 함수의 다음 줄부터 실행이 이어집니다 |
| **Ignore All** | 대화상자가 닫히고 실행이 이어집니다. 그 세션에서는 뒤에 나는 VME와 `Debug.Error()`에 대화상자가 뜨지 않고 알림만 뜹니다. 누를 때 같은 VME가 로그에 한 번 더 남고 알림도 한 번 더 뜹니다 |
| **Show Details...** | 버튼 아래에 VME 전체 글(`Stack trace:`의 모든 줄)이 든 칸이 펼쳐지고, 버튼 이름이 <strong>Hide Details...</strong>로 바뀝니다. 대화상자는 닫히지 않습니다 |

위키(Script Editor)는 **Stop** 버튼도 적지만, 이 대화상자에는 없습니다.

엔진 문서(Command line interface)에 따르면 시작 매개변수 `-VMErrorMode`로 VME를 알리는 방법을 바꿉니다. `silent`는 조용히 계속하고, `log_only`는 로그에만 남기고 계속하며, `full`은 대화상자를 띄우고 로그에 남기고, `fatal`은 로그에 남기고 종료합니다. `-noThrow`는 VME를 비롯한 오류 대화상자를 모두 끕니다. `-VMErrorMode log_only`나 `-noThrow`로 띄운 Workbench에서는 VME와 `Debug.Error()`에 대화상자가 뜨지 않고 실행이 이어지지만, 오른쪽 아래 알림은 그대로 뜹니다.

### 알림

알림은 화면 오른쪽 아래, 작업 표시줄 위에 뜨고 몇 초 뒤 저절로 사라집니다(<FigRef id="ch05-vme-toast" />). 제목은 `Script`, 내용은 `Virtual Machine Exception occurred! Check log for more info.`입니다. 대화상자가 함께 뜰 때도 같은 알림이 뜹니다. 알림에는 원인이 없으므로 다음 절처럼 로그에서 찾습니다.

<Figure src="ch05/vme-toast.png" alt="VME 알림" id="ch05-vme-toast">VME 알림</Figure>

### 로그에서 VME 읽기

VME는 Log Console과 세 로그 파일 모두에 다음 꼴의 블록으로 남습니다. `<` `>`로 감싼 곳에 실제 값이 들어갑니다.

```text
<시각> SCRIPT    (E): Virtual Machine Exception

Reason: <원인>

Class:      '<클래스>'
Function: '<함수>'
Stack trace:
<파일>:<줄> Function <함수>
<파일>:<줄> Function <함수>
```

- `Reason:`은 원인입니다. null 참조로 메서드를 부르면 `NULL pointer to instance`이고, `Debug.Error()`는 넘긴 메시지입니다.
- `Class:` 줄이 없는 블록도 있습니다.
- `Stack trace:` 아래 첫 줄이 VME가 난 곳이고, 그 아래 줄이 그 함수를 부른 곳입니다.
- Remote Console에서 실행한 코드는 맨 아래에 `execCode:1 Function #main`으로 나옵니다.

알림만 보고 원인을 찾을 때는 Log Console이나 로그 파일에서 `Virtual Machine Exception` 또는 `Reason:`을 검색합니다. 찾은 위치로 갈 때는 Script Editor의 **Edit > Find Stack Trace**(<Kbd>Alt</Kbd>+<Kbd>G</Kbd>)를 씁니다. 열리는 **Find Stack Trace** 창에 로그의 `Stack trace:` 줄들을 붙여 넣고 **OK**를 누르면 **Find Results** 창에 그 파일이 나오고, 그 줄을 두 번 클릭하면 스택 트레이스가 가리키는 줄로 갑니다.

## Script Authorization Required

World Editor에서 Play를 처음 시작하면 **Script Authorization Required** 대화상자가 뜰 수 있습니다(<FigRef id="ch05-script-auth" />). 스크립트가 위험할 수 있는 메서드를 쓰려 할 때 허락을 묻는 대화상자입니다. 예를 들어 기본 게임의 스크립트는 다음과 같이 묻습니다.

```text
Allow script 'Scripts/Game/GameMode/Loadout/SCR_ArsenalManagerComponent.c:1101'
to access potentially dangerous method 'BaseContainerTools.LoadContainer'?
```

<Figure src="ch05/script-auth.png" alt="Script Authorization Required 대화상자" id="ch05-script-auth">Script Authorization Required 대화상자</Figure>

공식 스크립트 `SCR_ArsenalManagerComponent.c`의 1101행이 `BaseContainerTools.LoadContainer`를 부르려는 것입니다. 버튼은 **Yes**, **Yes to All**, **No**, **No to All** 넷입니다. 답할 때까지 Play는 시작되지 않습니다.

**Yes to All**로 답하면 그 세션에서는 다시 묻지 않지만, Workbench를 새로 띄우면 다시 묻습니다. **No**로 답하면 그 메서드를 허락하지 않은 채 Play가 시작되고, 다음 Play에서 다시 묻습니다. **No to All**로 답해도 Play는 시작되고, 그 세션에서는 다시 묻지 않습니다. 내 모드나 다른 모드의 스크립트가 묻는다면 경로와 메서드 이름을 읽고 답합니다.

위키(Startup Parameters)는 시작 매개변수 `-scriptAuthorizeAll`이 `RunCmd`, `RunProcess`, `KillProcess`와 프로필 폴더 밖의 파일 입출력에 대한 이 보안 확인을 끈다고 설명합니다. 엔진 문서(Command line interface)는 위험할 수 있는 스크립트 명령을 Workbench에서 자동으로 허락한다고 적습니다. 이 매개변수로 띄운 Workbench에서는 위의 `LoadContainer` 확인도 뜨지 않습니다.

## 디버거 화면

디버거로 실행을 멈추고 변수와 호출 순서를 보는 방법, 단계 실행의 뜻, 실습은 Script 책 15장에 있습니다. 여기서는 그때 보는 메뉴와 창을 정리합니다. 이 절의 화면은 Script 책 15장 실습처럼 컴포넌트의 `OnPostInit()` 안 줄에 브레이크포인트를 걸고 Play해 멈춘 모습입니다.

### 디버거가 붙는 대상

**Debug** 메뉴 맨 위에는 **Debug Game**, **Debug Workbench**, **Debug Custom**, **Debug Disabled**가 있습니다(<FigRef id="ch05-debug-menu" />). 그림에서는 **Debug Workbench**에 체크 표시가 있습니다. 이때 Script Editor 창 제목에는 `Debugging: ArmaReforgerWorkbenchSteamDiag.exe on port: 1000`이 붙습니다(<FigRef id="ch05-breakpoint-stop" />). **Debug Workbench**일 때 World Editor의 Play로 실행한 게임 코드는 브레이크포인트에서 멈춥니다. **Debug Game**이나 **Debug Disabled**를 고르면 창 제목에서 `Debugging: …` 부분이 사라지고, World Editor의 Play는 브레이크포인트에서 멈추지 않습니다.

**Debug Custom**으로 다른 포트에 붙는 방법과 게임·서버 실행 파일을 디버깅하는 방법은 Script 책 15장에서 다룹니다.

### Debug 메뉴

<Figure src="ch05/debug-menu.png" alt="Script Editor의 Debug 메뉴" id="ch05-debug-menu">Script Editor의 Debug 메뉴</Figure>

**Debug** 메뉴의 나머지 항목과 단축키는 다음과 같습니다. 비고 칸이 빈 키는 눌러서 동작을 확인한 키이고, '메뉴 표시'는 메뉴 항목 옆에 적혀 있는 키입니다. 각 동작의 뜻은 Script 책 15장의 표에 있습니다.

| 항목 | 단축키 | 비고 |
|---|---|---|
| **Continue** | <Kbd>F5</Kbd> | |
| **Step Into** | <Kbd>F11</Kbd> | |
| **Step Over** | <Kbd>F10</Kbd> | |
| **Step Out** | <Kbd>Shift</Kbd>+<Kbd>F11</Kbd> | |
| **Stop** | <Kbd>Shift</Kbd>+<Kbd>F5</Kbd> | 메뉴 표시 |
| **Toggle Breakpoint** | <Kbd>F9</Kbd> | |
| **Dump Classes** | 없음 | — |
| **Recompile File on Host** | <Kbd>Ctrl</Kbd>+<Kbd>F7</Kbd> | |
| **Console Execute** | <Kbd>F6</Kbd> | |

**Debug Workbench**일 때 **Stop**은 브레이크포인트에서 멈춘 동안과 편집 모드에서 흐리게 표시되고, Play가 멈추지 않고 도는 동안에는 켜져 있습니다. Play는 <Kbd>Esc</Kbd>나 **Game > Exit game**으로 끝냅니다(11장).

<Kbd>Ctrl</Kbd>+<Kbd>F7</Kbd>(**Recompile File on Host**)은 Play 중인 게임에서 지금 파일을 다시 컴파일합니다. 저장하지 않은 고친 내용도 들어가고, 다음 호출부터 고친 코드가 실행됩니다. **Dump Classes**는 스크립트 클래스마다 이름과 선언 위치(파일과 줄)를 로그에 출력합니다. 멈춘 곳이 없을 때 **Continue**(<Kbd>F5</Kbd>)를 누르면 World Editor의 플레이 모드가 시작되지만, 이렇게 시작한 Play에서는 창 제목에서 `Debugging: …`이 빠지고 브레이크포인트에서 멈추지 않습니다. 브레이크포인트에서 멈추게 하려면 World Editor의 Play 버튼으로 시작합니다.

Script Editor 왼쪽 위 **Debug** 창의 버튼 다섯 개는 **Debug** 메뉴와 같은 아이콘을 씁니다. 왼쪽부터 **Continue**, **Step Over**, **Step Into**, **Step Out**, **Stop** 버튼이고, 마우스를 올리면 툴팁에 `Continue (F5)`처럼 이름과 단축키가 나옵니다.

### 브레이크포인트와 Breakpoints 창

편집 영역에서 줄에 커서를 두고 <Kbd>F9</Kbd>를 누르면 그 줄의 줄 번호 오른쪽에 빨간 점이 생기고, **Breakpoints** 창에 `Scripts/Game/…/파일 이름.c : 16`처럼 파일 경로와 줄 번호가 든 항목이 생깁니다. 항목 앞의 체크 상자를 끄면 그 브레이크포인트에서 멈추지 않고, 다시 켜면 멈춥니다. 같은 줄에서 **Debug > Toggle Breakpoint**를 다시 고르면 브레이크포인트가 지워집니다.

Breakpoints 창 위쪽에는 검색 칸과 버튼 셋이 있습니다. X는 **Delete all breakpoints**로, 누르면 `Are you sure?`를 묻는 창이 뜹니다. 빨간 원은 **Enable all breakpoints**, 빈 빨간 원은 **Disable all breakpoints**이고, 모두 끄면 항목의 체크가 빠지고 줄 번호 옆의 점도 빈 원이 됩니다.

줄 번호 옆을 클릭해도 브레이크포인트가 생기고, 다시 클릭하면 지워집니다. 한글이 든 파일에서는 빨간 점도 줄 번호와 함께 코드 줄과 어긋나 그려질 수 있으므로, 브레이크포인트를 건 줄은 **Breakpoints** 창 항목의 줄 번호로 확인합니다(4장). `{`만 있는 줄처럼 실행할 수 없는 줄에 건 브레이크포인트는 빈 원 안에 `!`로 표시되고, 거기서는 멈추지 않습니다. 위키와 Script 책 15장은 지금 돌고 있는 코드와 편집기의 코드가 다르면 브레이크포인트가 무효로 표시된다고 설명합니다. {/* 확인 대기: 지금 돌고 있는 코드와 편집기의 코드가 다를 때 무효 브레이크포인트의 표시 */}

실행이 브레이크포인트에 닿으면 Script Editor 창이 앞으로 나오고, 멈춘 줄의 빨간 점 위에 주황색 화살표가 표시됩니다(<FigRef id="ch05-breakpoint-stop" />). 상태 줄에는 멈춘 클래스, 메서드, 줄 번호가 나오고, **Watch**와 **Callstack** 창이 채워집니다.

<Figure src="ch05/breakpoint-stop.png" size="full" alt="브레이크포인트에서 멈춘 Script Editor" id="ch05-breakpoint-stop">브레이크포인트에서 멈춘 Script Editor</Figure>

### Watch와 툴팁

멈추면 **Watch** 창에 지금 위치의 `this`, 매개변수, 지역 변수가 따로 더하지 않아도 나옵니다(<FigRef id="ch05-watch" />). 한 줄은 `타입 이름 = 값` 꼴이고, 객체는 줄 앞의 화살표를 눌러 펼치면 멤버가 보입니다. `this`는 `Class this = …`로 나오고, 정적 메서드에서 멈추면 `Class this = NULL`입니다. 창 위쪽에는 검색 칸이 있습니다. 실행이 이어진 뒤에도 Watch 창에는 마지막으로 멈췄을 때의 값이 흐린 글자로 남습니다.

Watch 창에는 식을 직접 입력하는 칸이 없습니다. 줄을 오른쪽 클릭해 **Add watch**를 고르면 그 줄 앞에 눈 아이콘이 붙고, 그 줄을 다시 오른쪽 클릭하면 메뉴 항목이 **Remove watch**로 바뀝니다. {/* 확인 대기: Add watch로 눈 아이콘을 붙인 줄이 하는 일 */}

<Figure src="ch05/watch.png" alt="멈춘 상태의 Watch 창" id="ch05-watch">멈춘 상태의 Watch 창</Figure>

멈춘 상태에서 편집 영역의 변수 이름에 마우스를 올리면 값이 작은 창으로 보입니다(<FigRef id="ch05-hover" />). 엔티티라면 주소, `@"ENTITY:…"` 링크 문자열, 엔티티 이름과 클래스, 위치가 한 줄로 나오고, 길면 끝이 잘립니다. 클래스 이름에 올리면 그 클래스의 선언 줄과 문서 주석이 나옵니다.

<Figure src="ch05/hover.png" size="full" alt="변수 위에 마우스를 올린 툴팁" id="ch05-hover">변수 위에 마우스를 올린 툴팁</Figure>

### Callstack

**Callstack** 창은 지금 위치까지 거쳐 온 메서드를 한 줄에 하나씩 보여 줍니다(<FigRef id="ch05-callstack" />). 줄마다 `TAG_GeneratorComponent::OnPostInit()`처럼 클래스와 메서드 이름이 나오고, 그 뒤에 파일 경로와 줄 번호가 붙습니다. 정적 메서드는 `::SayHello()`처럼 클래스 이름 없이 나옵니다. 맨 위 줄이 지금 멈춘 곳이고, 아래로 갈수록 부른 쪽입니다. 그래서 Script 책 15장과 위키의 설명대로 아래에서 위로 읽으면 호출 순서가 됩니다.

<Figure src="ch05/callstack.png" alt="Callstack 창" id="ch05-callstack">Callstack 창</Figure>

엔진이 부른 `OnPostInit()`에서 멈추면 한 줄뿐입니다. Remote Console에서 부른 코드가 멈추면 맨 아래 줄이 `::#main()`입니다. 로그의 `Stack trace:`에서 본 `execCode:1 Function #main`과 같은 자리입니다. 파일 경로가 붙은 줄을 두 번 클릭하면 그 파일의 그 줄로 가고, `::#main()` 줄은 두 번 클릭해도 골라지기만 합니다.

### debug 문과 Breakpoints 창

Script 책 15장은 코드 안의 `debug;` 문이 그 자리에서 브레이크포인트를 건다고 설명합니다. 스크립트를 컴파일하면 `debug;`가 든 줄마다 **Breakpoints** 창에 체크된 항목이 저절로 생깁니다. 그 항목의 체크를 끄거나 항목을 지우면 `debug;`에서도 멈추지 않고, 체크를 다시 켜면 멈춥니다. 지운 항목은 **Validate and Reload Scripts**로 다시 컴파일하면 다시 생깁니다.

## 정리

<Summary>

- Remote Console에서 실행 환경을 고르고(Script 책 예제는 `Game`) **Run**을 누르면 코드가 실행됩니다. 결과는 Output에 나오고, 월드를 열거나 Play하지 않아도 실행됩니다.
- 출력은 Script Editor의 Output, 메인 창과 World Editor의 Log Console, 로그 파일 세 곳에 남습니다. 엔티티 링크는 World Editor의 Log Console에서 누릅니다.
- 로그 파일은 `…\ArmaReforgerWorkbench\logs` 아래 세션 폴더에 `console.log`, `script.log`, `error.log`로 남습니다.
- VME가 나면 화면 오른쪽 아래에 알림이 뜨고, 새로 띄운 세션에서는 **Virtual machine exception** 대화상자(**Debug**, **Ignore**, **Ignore All**, <strong>Show Details...</strong>)도 함께 뜹니다. 그 세션에서 **Ignore All**을 누르거나 Play를 시작한 뒤에는 알림만 뜹니다. 원인과 위치는 로그의 `Reason:`과 `Stack trace:`에서 찾습니다.
- **Script Authorization Required**는 세션의 첫 Play 때 스크립트가 위험할 수 있는 메서드를 쓰려 하면 뜨고, **Yes**, **Yes to All**, **No**, **No to All**로 답합니다.
- 디버거는 **Debug** 메뉴(**Continue** <Kbd>F5</Kbd>, **Step Over** <Kbd>F10</Kbd>, **Toggle Breakpoint** <Kbd>F9</Kbd> 등), Breakpoints 창의 체크 상자, Watch의 `this`와 매개변수, 위가 지금 위치인 Callstack으로 봅니다.

</Summary>
